# 审核页面后端接口需求（Films/Playlists/Torrents）

## 概述
- 目的：支撑管理端审核页面对影片/片单/种子进行“列表筛选 + 审核动作 + 审核历史”完整流程；同时与用户端的审核开关行为保持一致。
- 范围：新增或增强管理端列表接口、统一审核动作接口、统一审核历史查询接口、审核开关读取接口。

## 审核开关（只读）
- 设置键：`film.review`、`playlist.review`、`torrent.review`（布尔，默认 `false`）
- 行为：开启后，用户端列表仅展示 `approved` 内容；新建内容为 `pending`，通过后才可见；已通过内容可再次被 `rejected` 后不可见
- 只读端点：`GET /settings/review-switches`
  - 成功响应示例：
  ```json
  {
    "code": 1000,
    "message": "操作成功",
    "data": {
      "filmReview": true,
      "playlistReview": false,
      "torrentReview": true
    },
    "path": "/settings/review-switches",
    "timestamp": "2025-11-28T08:00:00.000Z"
  }
  ```
  - 权限建议：仅具备审核权限的用户可读取

## 统一响应与错误码
- 成功统一：`{ code:1000, message:'操作成功', data, path, timestamp }`
- 错误码映射：`400→9400`、`401→9401`、`403→9403/9405`、`404→9404`、`5xx→9500`

## 管理端列表接口（需支持按审批状态筛选）

### 影片（Films）
- 新增或增强：`POST /films/admin/list`
- 请求示例：
  ```json
  {
    "page": 1,
    "limit": 20,
    "keyword": "哈利波特",
    "approvalStatus": "pending",
    "category": "film",
    "year": "2001",
    "ratingMin": 7,
    "ratingMax": 10,
    "genreIds": ["fantasy"],
    "enabled": true,
    "sortBy": "approvedAt",
    "order": "DESC"
  }
  ```
- 成功响应示例：
  ```json
  {
    "code": 1000,
    "message": "操作成功",
    "data": {
      "items": [
        {
          "id": "178...",
          "title": "哈利·波特与魔法石",
          "approvalStatus": "pending",
          "approvedAt": null,
          "posterUrl": "...",
          "uploader": { "username": "UploaderX", "reputation": 88 }
        }
      ],
      "total": 1,
      "page": 1,
      "limit": 20
    },
    "path": "/films/admin/list",
    "timestamp": "2025-11-28T08:00:00.000Z"
  }
  ```
- 说明：现有 `POST /films/admin/list-pending` 仅覆盖 `pending`；为统一体验建议改为通用列表并支持 `approvalStatus=pending|approved|rejected` 与 `approvedAt` 排序

### 种子（Torrents）
- 管理员列表：`POST /torrents/admin/list-torrents`
- 请求（高级规则）示例：
  ```json
  {
    "page": 1,
    "limit": 20,
    "keyword": "Interstellar",
    "sortBy": "approvedAt",
    "order": "DESC",
    "logic": "AND",
    "rules": [
      { "field": "approvalStatus", "op": "Equal", "value": "pending" }

  }
  ```
- 成功响应示例：
  ```json
  {
    "code": 1000,
    "message": "操作成功",
    "data": {
      "items": [
        {
          "id": "tor_1001",
          "title": "Interstellar.2014.1080p.BluRay.x264",
          "approvalStatus": "pending",
          "approvedAt": null,
          "uploader": { "username": "Uploader123", "reputation": 88 },
          "category": "film",

  ```
- 说明：如当前未支持 `approvalStatus` 字段过滤，请补充字段映射与查询逻辑；`approvedAt` 排序在模型中已声明

## 审核动作接口（统一已存在）
- 影片：`POST /films/review`
- 片单：`POST /playlists/review`
- 种子：`POST /torrents/review`
- 请求：`{ id: string, action: 'approve' | 'reject', note?: string }`
- 返回：统一响应结构
- 说明：建议在执行审核动作时写入审核日志（见下），并在被驳回时支持记录原因 `note`

## 审核历史接口（新增）
- 统一查询端点：`GET /audit/history?type=<film|playlist|torrent>&resourceId=<id>`
- 返回示例：
  ```json
  {
    "code": 1000,
    "message": "操作成功",
    "data": {
      "items": [
        { "reviewer": "AdminUser", "action": "approved", "note": "信息完整", "timestamp": "2025-11-28T08:00:00.000Z" },
        { "reviewer": "ModeratorA", "action": "rejected", "note": "重复资源", "timestamp": "2025-11-28T10:00:00.000Z" }
      ],
      "total": 2
    },
    "path": "/audit/history",
    "timestamp": "2025-11-28T11:00:00.000Z"
  }
  ```
- 行为：每次 `approve/reject` 写入一条日志，包含操作者、动作、备注与时间戳；审核页详情抽屉展示该时间线

## 用户端受影响的接口（保持现有行为）
- 影片：`POST /films/list-films` → 审核开启时仅返回 `approved`
- 片单：`POST /playlists/list` → 审核开启时仅返回 `approved`
- 种子：`POST /torrents/list`、`POST /torrents/user/list-torrents` → 审核开启时仅返回 `approved`
- 详情页：建议前端以列表结果为准进行导航，避免直接访问未通过审核的 ID

## 前端对接说明（便于联调）
- 审核页地址：`/review`（权限守卫，需 `review:write`）
- 已对接：
  - 种子管理员列表接口（含 `approvalStatus` 规则筛选）
  - 影片管理员通用列表（`approvalStatus` + `approvedAt` 排序）
  - 片单管理员通用列表（`approvalStatus` + `approvedAt` 排序）
  - 三类统一审核动作接口（执行后本地状态更新）
  - 审核开关只读展示（`GET /settings/review-switches`）
  - 审核历史统一查询（时间线展示）

## 参数约定与一致性
- `approvalStatus`：`pending | approved | rejected`
- 排序字段：建议统一支持 `approvedAt`（最新审批时间）
- 响应包裹：统一 `{ code, message, data, path, timestamp }`；前端已兼容直返与包裹两种风格

## 验证场景
- 审核开关开启：用户端仅见 `approved`；管理端审核页可筛选 `pending/approved/rejected`
- 审核动作：`pending` → `approved/rejected` 后，列表与统计更新；历史查询返回时间线
