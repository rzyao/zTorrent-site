# 权限配置驱动（Config‑First）实施说明

## 目标
- 以 `config/permissions.yaml` 作为权限的唯一信源，统一定义菜单/页面/动作的层级与权限码。
- 通过生成 `src/permissions/permissions.gen.ts`，在代码层面以类型与常量约束权限使用，避免散落字符串与拼写错误。

## 文件与结构
- `config/permissions.yaml`
  - 字段：`name`、`code`、`type(menu|page|action)`、`children[]`、`actions[]`、`api(可选)`、`description(可选)`、`roles(可选)`。
  - 示例：
    ```yaml
    - name: 系统管理
      code: sys:manage
      type: menu
      children:
        - name: 用户管理
          code: sys:user
          type: page
          actions:
            - { name: 查询, code: sys:user:query, api: GET /users }
            - { name: 新增, code: sys:user:add,   api: POST /users }
    ```

## 生成流程
- 生成脚本：`scripts/generate-permissions.mjs`
  - 解析 YAML，使用 `ajv` 按 JSON Schema 校验结构与 `code` 唯一性，校验 `api` 形如 `METHOD /path`。
  - 生成 `src/permissions/permissions.gen.ts`：
    - `PermissionCode` 联合类型
    - `ALL_PERMISSION_CODES` 扁平列表
    - `PERMS` 嵌套常量对象（若节点同时为自身与父节点，使用 `_` 字段保存自身 code）
- npm 脚本：
  - `prepare` 与 `prebuild` 会自动执行生成脚本；
  - 手动执行：`pnpm permissions:gen`

## 前端接入
- 路由守卫：`src/routes/AppRoutes.tsx`
  - `requiredPermissions` 改为使用 `PermissionCode[]`，示例：`requiredPermissions={[PERMS.review.write]}`。
- 上下文校验：`src/context/AccessContext.tsx`
  - 开发模式下对后端返回的权限码进行唯一信源交叉校验，输出未定义 `code` 的告警。
- UI 条件渲染：`src/layouts/Header.tsx`
  - 使用 `PERMS` 常量进行按钮/入口条件渲染，保持展示与路由一致的授权语义。

## 约束与不兼容
- 统一改用 `permissions.gen.ts` 的类型与常量，不再使用自由字符串；旧用法不做兼容保留。
- 新增或调整权限需在 `permissions.yaml` 中维护；前端仅消费生成结果。
- 后端返回的权限码需与 YAML 一致；否则在开发环境会输出告警。

## 常见问题
- 重复 `code`：生成脚本会中止并输出重复项列表；修复 YAML 后重试。
- `api` 格式错误：需形如 `METHOD /path`，如 `POST /users`。
- 对象嵌套：当同一段既是父节点又是具体权限码时，生成的 `PERMS.xxx` 会以 `PERMS.xxx._` 表示该段自身的权限码。
