# 断种功能后端对接文档

## 概述
- 页面：`DeadTorrentsPage`（`src/pages/DeadTorrents/index.tsx`）展示断种资源的三个视图：`hall`（断种大厅）、`myPublished`（我发布的）、`myDownloaded`（我下载的）。
- 排序：支持 `bounty`（悬赏总额）、`ratio`（分享率）、`time`（断种时长）。前端示例数据中的 `deadTime` 为字符串，后端需提供可排序的数值型时长。
- 统计：头部统计卡片与警告提示依赖当前视图的总数、总悬赏、平均悬赏等汇总数据。
- 操作：
  - 大厅与“我发布的”提供“恢复做种”；
  - “我下载的”提供“追加悬赏”；工具栏支持“批量悬赏”（我下载的）与“批量恢复做种”（我发布的）。

## 前端数据映射
- 列表项模型（`DeadTorrent`）字段：`id, title, size, uploaded, downloaded, ratio, deadTime, potentialBonus, lastSeedTime, seeders, poster, category, reason, publisher, bounty, bountyCount`。
- 为支持排序与统计，后端建议在响应中同时提供数值化字段：
  - `sizeBytes`、`uploadedBytes`、`downloadedBytes`（字节数）；
  - `deadDurationMinutes`（断种时长，分钟）；
  - `lastSeedAt`（ISO 时间戳）；
  - 文本展示字段仍保留（如 `size`, `deadTime`, `lastSeedTime`）。

## 鉴权与权限
- 所有接口均需鉴权（建议 `Authorization: Bearer <token>`）。
- 视图权限：
  - `scope=myPublished` 仅返回当前用户发布的断种资源；
  - `scope=myDownloaded` 仅返回当前用户曾下载且已断种的资源。
- 操作权限：
  - “恢复做种”仅允许发布者或已获授权的做种者发起；
  - “追加悬赏”允许符合站点规则的用户发起（页面当前仅在 `myDownloaded` 入口暴露）。

## 接口总览
- GET `/api/dead-torrents` 断种列表查询（含可选统计）
- GET `/api/dead-torrents/stats` 当前视图统计数据
- POST `/api/torrents/{id}/bounty` 追加悬赏（单条）
- POST `/api/dead-torrents/bounty/batch` 批量追加悬赏（我下载的）
- POST `/api/torrents/{id}/seed/resume` 恢复做种（单条）
- POST `/api/dead-torrents/seed/resume/batch` 批量恢复做种（我发布的）

## 列表查询
GET `/api/dead-torrents`

查询指定视图下的断种列表，并支持服务端排序、分页与可选统计。

请求参数（Query）：
- `scope` 枚举：`hall | myPublished | myDownloaded`，默认 `hall`
- `sortBy` 枚举：`bounty | ratio | time`。为避免歧义，后端可接受 `time` 与别名 `deadDuration`，统一映射到 `deadDurationMinutes`
- `order` 枚举：`desc | asc`，默认 `desc`
- `page` 数字：页码，默认 `1`
- `pageSize` 数字：每页数量，默认 `20`
- 可选过滤（前端暂未使用，预留）：`category`、`publisher`、`keyword`

响应（200）：
```json
{
  "items": [
    {
      "id": "1",
      "title": "星际穿越 Interstellar (2014) 4K UHD BluRay HEVC",
      "size": "96.5 GB",
      "sizeBytes": 103658807296,
      "uploaded": "289.5 GB",
      "uploadedBytes": 310940016640,
      "downloaded": "145.2 GB",
      "downloadedBytes": 155979816960,
      "ratio": 1.99,
      "deadTime": "15天8小时",
      "deadDurationMinutes": 22320,
      "lastSeedTime": "2024-11-23 14:30",
      "lastSeedAt": "2024-11-23T14:30:00Z",
      "seeders": 0,
      "poster": "https://...",
      "category": "电影",
      "reason": "所有做种者都已停止",
      "publisher": "MovieMaster",
      "bounty": 2580.0,
      "bountyCount": 23
    }
  ],
  "stats": {
    "total": 120,
    "totalBounty": 356000.0,
    "avgBounty": 2966.7,
    "avgDeadDurationMinutes": 18720
  },
  "pagination": { "page": 1, "pageSize": 20, "total": 120 }
}
```

错误响应：
- 401 未认证；
- 403 无权限（如访问 `myPublished` 非本人数据）；
- 400 非法参数（排序字段、页码越界等）。

排序规则：
- `sortBy=bounty`：按 `bounty` 数值降序；
- `sortBy=ratio`：按 `ratio` 数值降序；
- `sortBy=time|deadDuration`：按 `deadDurationMinutes` 数值降序。

## 统计数据
GET `/api/dead-torrents/stats`

当列表接口不返回 `stats` 字段时，可单独获取当前视图统计。

请求参数（Query）：
- `scope`：`hall | myPublished | myDownloaded`

响应（200）：
```json
{
  "total": 120,
  "totalBounty": 356000.0,
  "avgBounty": 2966.7,
  "avgDeadDurationMinutes": 18720
}
```

## 追加悬赏（单条）
POST `/api/torrents/{id}/bounty`

为指定断种资源追加悬赏（前端入口：列表卡片在 `myDownloaded` 视图）。

请求体（JSON）：
```json
{ "amount": 200.0, "note": "希望尽快恢复做种" }
```
- `amount`：本次追加的金币数量（>0）；
- `note`：可选备注。

响应（200）：
```json
{ "id": "202", "bounty": 3400.0, "bountyCount": 32 }
```

错误响应：
- 404 资源不存在或非断种；
- 403 用户不具备追加权限或额度不足；
- 409 操作冲突（如悬赏已关闭）。

---

## 批量追加悬赏
POST `/api/dead-torrents/bounty/batch`

用于“我下载的”工具栏的“批量悬赏”。

请求体（JSON）：
```json
{
  "items": [
    { "id": "201", "amount": 100.0 },
    { "id": "202", "amount": 200.0 }
  ]
}
```

响应（200）：
```json
{
  "updated": 2,
  "results": [
    { "id": "201", "bounty": 2680.0, "bountyCount": 24, "status": "ok" },
    { "id": "202", "bounty": 3400.0, "bountyCount": 32, "status": "ok" }
  ]
}
```

错误响应：
- 400 参数校验失败；
- 207 部分成功（使用 `results` 标注失败原因）。

## 恢复做种（单条）
POST `/api/torrents/{id}/seed/resume`

前端在 `hall` 与 `myPublished` 视图中提供“恢复做种”入口。

请求体（JSON）：
```json
{ "clientId": "qBittorrent-XYZ", "note": "重新挂载硬盘后可恢复" }
```
- `clientId`：发起恢复的客户端标识；
- `note`：可选备注。

响应（200）：
```json
{ "id": "101", "status": "accepted", "next": "系统将验证做种并通知悬赏者" }
```

错误响应：
- 403 非发布者或无恢复权限；
- 409 状态冲突（已恢复做种或恢复中）。

---

## 批量恢复做种
POST `/api/dead-torrents/seed/resume/batch`

用于“我发布的”工具栏的“批量恢复做种”。

请求体（JSON）：
```json
{ "ids": ["101", "102"], "clientId": "qBittorrent-XYZ" }
```

响应（200）：
```json
{ "accepted": 2, "results": [ { "id": "101", "status": "accepted" }, { "id": "102", "status": "accepted" } ] }
```

## 业务规则与定义
- 断种判定：`seeders == 0` 且最近做种时间超过站点阈值（例如 > 24 小时）。
- 悬赏累计：`bounty` 为当前悬赏总额，`bountyCount` 为参与悬赏的用户数。
- 可选字段：`potentialBonus`（前端展示的可能损失奖励）为衍生数据，后端可按站点规则计算或在列表中返回。

## 分页与刷新策略
- 列表接口返回 `pagination.total` 用于前端分页控件拓展；
- 前端在执行“追加悬赏/恢复做种”后应重新拉取当前 `scope` 下列表与统计；
- 为减少请求，可在列表接口一并返回 `stats`，避免多一次统计请求。

## 错误码建议
- 400 参数错误（排序字段非法、页码越界、金额无效等）；
- 401 未认证；
- 403 无权限（资源不属于当前用户或额度不足）；
- 404 资源不存在；
- 409 状态冲突；
- 500 服务器内部错误。

## 与前端组件的映射
- `Tabs`（`components/Tabs.tsx`）：`scope` 由 `hall | myPublished | myDownloaded` 映射；
- `Toolbar`（`components/Toolbar.tsx`）：`sortBy`、批量悬赏与批量恢复对应各自接口；
- `WarningAlert`（`components/WarningAlert.tsx`）：使用 `stats.total`、`stats.totalBounty`；
- `StatsCards`（`components/StatsCards.tsx`）：使用 `stats.total`、`stats.totalBounty`、`stats.avgBounty`，可扩展 `avgDeadDurationMinutes`；
- `DeadTorrentCard`（`components/DeadTorrentCard.tsx`）：渲染列表项字段并触发“恢复做种/追加悬赏”。

## 示例：请求组合
- 大厅按悬赏降序第 1 页：`GET /api/dead-torrents?scope=hall&sortBy=bounty&order=desc&page=1&pageSize=20`
- 我发布的按断种时长降序：`GET /api/dead-torrents?scope=myPublished&sortBy=time&order=desc`
- 批量恢复做种：`POST /api/dead-torrents/seed/resume/batch`
- 批量追加悬赏：`POST /api/dead-torrents/bounty/batch`
