# 小游戏功能后端对接文档

## 目标与范围
- 基于 `src/pages/Games` 页面与组件，反向分析前端数据需求，设计完整后端 API 规格，覆盖接口列表、参数、响应示例、错误码、鉴权、次数限制与反作弊。
- 统一响应包裹结构，遵循已有文档风格：`{ code, message, data, path, timestamp }`，认证采用 `Authorization: Bearer {token}`。
- 不做旧代码兼容；以当前 UI 行为为准，补齐必要的后端能力。

## 前端代码关联
- 页面容器
  - `src/pages/Games/index.tsx`：聚合头部、统计卡、游戏卡片与模态；`onNavigateMagicFarm` 用于跳转独立的“魔力农场”。
- 常量与类型
  - `src/pages/Games/constants.tsx`：游戏目录（签到/转盘/猜数字/答题/魔力农场），字段包含 `id/name/description/reward/difficulty/plays/highScore/route?`。
  - `src/pages/Games/types.ts`：`Game`、`UserStats`、`Difficulty`。
- 页面状态与动作
  - `src/pages/Games/hooks/useGamesState.ts`：`selectedGame` 打开模态；`userStats` 展示用户统计；`handleGameClick` 对农场触发跳转。
  - `src/pages/Games/components/StatsCards.tsx`：展示 `totalPlays/totalRewards/rank/level`。
  - `src/pages/Games/components/GameModal.tsx`：
    - 每日签到：`checkInDone`/`handleCheckIn()` → 需后端防重复与结算奖励。
    - 幸运转盘：`spinning`/`spinResult`/`handleSpin()` → 需后端扣除成本、生成奖励与日次数控制。
    - 猜数字：`guess`/`guessResult`/`handleGuess()` → 需后端判定与奖励、次数控制。
    - 答题闯关：占位题目与选项 → 需后端题库、判题与奖励。
    - 魔力农场：关闭模态并跳转 → 独立系统，另行对接。
- 规则文案（`index.tsx`）
  - 每日签到每天仅一次；转盘与猜数字每日有次数限制；答题难度越高奖励越丰富；作弊或外挂将永久封禁；奖励“魔力值”可用于兑换上传流量、VIP 等。

## 统一鉴权
- 认证：所有受保护接口需 `Authorization: Bearer {token}`。
- 权限建议：统一资源 `games:*`（例如 `games:play`、`games:spin`、`games:guess`、`games:quiz`），具体由网关或服务鉴权实现。


## 数据模型
- Game（小游戏目录项，服务端返回时不含前端图标）
  - `id:number`、`name:string`、`description:string`、`reward:number`、`difficulty:'easy'|'medium'|'hard'`、`plays:number`、`highScore:number`、`route?:'magicfarm'`。
- UserStats（用户统计）
  - `totalPlays:number`、`totalRewards:number`、`rank:number`、`level:number`。
- SpinResult（转盘结算）
  - `cost:number`（扣除魔力值）、`reward:number`、`remainingSpins:number`。
- GuessResult（猜数字结算）
  - `result:'hit'|'low'|'high'`、`reward?:number`、`remainingGuesses:number`。
- QuizQuestion / QuizAnswerResult（答题）
  - QuizQuestion：`{ id:string, text:string, options:string[], difficulty:'easy'|'medium'|'hard' }`
  - QuizAnswerResult：`{ correct:boolean, reward?:number, nextQuestionAvailable:boolean }`
- CheckInResult（签到）
  - `reward:number`、`nextAvailableAt:string(ISO)`。
- Limits（日次数与冷却）
  - `spin:{ dailyLimit:number, used:number }`、`guess:{ dailyLimit:number, used:number }`、`checkin:{ doneToday:boolean }`。

## 接口列表（按功能模块）

### 游戏目录与用户统计
- GET `/games/catalog`
  - 描述：获取可用小游戏目录，便于前端渲染卡片与奖励文案。
  - Headers：`Authorization: Bearer {token}`。
  - Query：无（按当前用户与站点配置返回）。
  - 200：`{ code:0, data: Game[] }`
- GET `/games/user-stats`
  - 描述：获取当前用户的统计数据（总游玩、累计奖励、排行榜、等级）。
  - 200：`{ code:0, data: UserStats }`
- GET `/games/limits`
  - 描述：获取当前用户今日各玩法的次数/冷却状态。
  - 200：`{ code:0, data: Limits }`

### 每日签到
- POST `/games/checkin`
  - 描述：当日签到，发放固定奖励，防重复。
  - Body：无（从认证用户识别）。
  - 200：`{ code:0, data: CheckInResult }`
  - 错误：`409`（今日已签到）、`429`（冷却中）。

### 幸运转盘
- POST `/games/spin`
  - 描述：执行一次转盘；服务端扣除成本并生成奖励，返回剩余次数。
  - Body：`{}`（如有多主题转盘可扩展 `theme?:string`）。
  - 200：`{ code:0, data: SpinResult }`
  - 错误：`402`（余额不足，若采用付费成本）、`429`（超出日次数）。

### 猜数字
- POST `/games/guess`
  - 描述：提交一次猜测，由服务端判定结果并在命中时结算奖励；返回今日剩余次数。
  - Body：`{ guess:number }`（范围 1–100）。
  - 200：`{ code:0, data: GuessResult }`
  - 错误：`422`（超出范围/非数字）、`429`（超出日次数）。

### 答题闯关
- GET `/games/quiz/question`
  - 描述：拉取一道题目；可按难度定级或服务端自适应。
  - Query：`difficulty?:'easy'|'medium'|'hard'`
  - 200：`{ code:0, data: QuizQuestion }`
- POST `/games/quiz/answer`
  - 描述：提交答案并返回是否正确与奖励；可由服务端控制下一题是否可用。
  - Body：`{ questionId:string, answerIndex:number }`
  - 200：`{ code:0, data: QuizAnswerResult }`
  - 错误：`404`（题目失效）、`429`（超出日次数/节奏限制）。

### 魔力农场（跳转）
- 说明：当前页面通过 `route:'magicfarm'` 跳转至独立模块；农场接口另行维护在《魔力农场后端对接文档》或相应模块文档中。

## 设计原因与取舍说明
- 统一响应包裹结构：与既有文档一致，便于前端通用处理与日志追踪。
- 服务端结算奖励与次数：前端目前为演示逻辑（随机/本地状态），正式环境需服务端统一可信结算并做限频与反作弊。
- 限制与规则外显：提供 `/games/limits` 以便页面提示“次数限制/今日已签到”等状态，减少无效点击。
- 难度影响奖励：答题支持难度枚举，与 `Game.difficulty` 对齐，便于后端策略控制。
- 农场独立：保留 `route:'magicfarm'` 的跳转约定，接口文档分模块维护，降低耦合。

## 集成注意事项
- 令牌注入：后端接受 `Authorization: Bearer`；前端在全局 API 客户端统一设置。
- 速率限制：对签到/转盘/猜数字/答题接口建议加入 429 防刷（账号与 IP 双维度）。
- 反作弊：
  - 服务端持有源随机性（转盘/猜数目标值/题库）；前端不暴露关键参数。
  - 检测异常行为（极短时间内高频调用、异常奖励偏态、机器行为特征）。
  - 标记并封禁违规用户，与页面“作弊或使用外挂将被永久封禁”文案一致。
- 经济与账户：奖励“魔力值”计入统一账户；转盘如有成本需检查余额，失败返回 `402` 或业务码。
- 国际化与文案：前端以中文展示为主，服务端字段为英文枚举与数值，避免多语言耦合。

## 与前端字段映射示例
- 统计卡（`src/pages/Games/components/StatsCards.tsx`）
  - 映射：`userStats.*` ← `/games/user-stats` 的 `UserStats`。
- 游戏目录（`src/pages/Games/constants.tsx` → 可改为服务端返回）
  - 映射：`Game[]` ← `/games/catalog`；前端忽略 `icon`，保留 `reward/difficulty/route` 等。
- 每日签到（`GameModal` 选项 1）
  - 映射：`checkInDone` ← `/games/checkin` 成功后以当日状态更新；奖励金额取 `Game.reward` 或服务端计算结果。
- 幸运转盘（`GameModal` 选项 2）
  - 映射：按钮触发 `/games/spin`；展示 `SpinResult.reward` 与 `remainingSpins`；禁用状态依据 `spinning` 与服务端限频。
- 猜数字（`GameModal` 选项 3）
  - 映射：输入提交 `/games/guess`；展示 `GuessResult.result` 与命中时 `reward`；根据 `remainingGuesses` 控制交互。
- 答题闯关（`GameModal` 选项 4）
  - 映射：先拉取 `/games/quiz/question` 渲染问题与选项；提交 `/games/quiz/answer` 展示反馈与奖励。
- 魔力农场（`GameModal` 选项 5）
  - 映射：保持跳转 `onNavigateMagicFarm()`；接口文档独立维护。

> 如需生成 OpenAPI/Swagger，可按本规范录入路径、枚举与响应包裹结构，并分组为 GamesCatalog、GamesPlay（checkin/spin/guess/quiz）、GamesStats、GamesLimits。
