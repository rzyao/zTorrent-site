# 公告功能后端对接文档

## 目标与范围
- 基于 `src/pages/Announcements` 页面与相关组件，反向分析前端数据需求，设计后端 API 规格，覆盖接口列表、参数、响应示例、错误码、鉴权与分页/筛选约定。
- 设计遵循项目既有风格：统一响应包裹结构、列表查询优先采用 `POST + JSON`、支持 `Authorization: Bearer {token}`。
- 不做旧代码兼容；以当前 UI 行为为准，补齐必要的后端能力（列表、详情、统计、标记已读）。

## 前端代码关联
- 页面容器
  - `src/pages/Announcements/index.tsx`：装配筛选栏、公告卡片列表、详情侧栏与统计侧栏。
- 数据模型与常量
  - `src/pages/Announcements/types.ts`：定义 `Announcement`、`AnnouncementType`。
  - `src/pages/Announcements/constants.ts`：`MOCK_ANNOUNCEMENTS: Announcement[]` 本地示例数据。
- 状态与筛选逻辑
  - `src/pages/Announcements/hooks/useAnnouncements.ts`：`filter('all'|type)` → `filteredAnnouncements`；`isPinned` 拆分为 `pinnedAnnouncements/normalAnnouncements`。
- 组件展示
  - `FilterBar.tsx`：筛选项 `value: AnnouncementType|'all'`。
  - `AnnouncementCard.tsx`：字段展示 `title/content/type/author/publishDate/isPinned/isRead/views/comments`。
  - `AnnouncementDetail.tsx`：详情展示同上；点击来自 `index.tsx` 的 `handleCardClick`（向上抛出 `onAnnouncementClick(id)`）。
  - `StatsSidebar.tsx`：统计口径基于当前 `announcements`（总数/未读数/置顶数）。

## 统一鉴权
- 列表与详情：可根据站点策略开放匿名访问；默认支持带 Token 访问以获取“未读态”等与用户相关字段。
- 统计与标记已读：需登录；Headers 统一为 `Authorization: Bearer {token}`。


## 分页与筛选约定
- 列表请求采用 `POST + JSON Body`，字段：
  - `page`(默认1)、`pageSize`(默认20，最大100)、`type`(`'all'|'system'|'event'|'rule'|'maintenance'`)。
- 列表响应统一：`data: { items: Announcement[], total: number }`。
- 默认排序：`publishDate` 倒序；置顶由前端基于 `isPinned` 客户端拆分展示。

## 数据模型
- Announcement（公告）
  - `id`(string)、`title`(string)、`content`(string, Markdown/HTML 可选)、`type`(enum: `system|event|rule|maintenance`)、`author`(string｜或 `{id,name}`)
  - `publishDate`(string, `YYYY-MM-DD HH:mm` 或 ISO)、`isPinned`(boolean)、`isRead`(boolean, 与用户相关)、`views`(number)、`comments`(number)

## 接口列表（公告模块）

### 列表与详情
- POST `/announcements/list`
  - 描述：分页检索公告列表，支持类型筛选；返回包含置顶与普通公告（通过 `isPinned` 区分）。
  - Headers：可选 `Authorization: Bearer {token}`（若需返回用户相关 `isRead`）。
  - Body：`{ page?:number, pageSize?:number, type?:'all'|'system'|'event'|'rule'|'maintenance' }`
  - 200：`{ code:0, message:'OK', data:{ items: Announcement[], total:number }, path, timestamp }`
  - 错误：400/401/403/500。

- POST `/announcements/detail`
  - 描述：获取公告详情。
  - Headers：可选 `Authorization: Bearer {token}`。
  - Body：`{ id:string }`
  - 200：`{ code:0, data: Announcement }`
  - 错误：404（不存在）。

### 统计与已读
- POST `/announcements/stats`
  - 描述：返回当前筛选条件下的统计数据；用于 `StatsSidebar` 展示。
  - Headers：`Authorization: Bearer {token}`。
  - Body：`{ type?:'all'|'system'|'event'|'rule'|'maintenance' }`
  - 200：`{ code:0, data:{ total:number, unread:number, pinned:number } }`

- POST `/announcements/mark-read`
  - 描述：将某公告标记为已读（常在用户点击卡片后触发）。
  - Headers：`Authorization: Bearer {token}`。
  - Body：`{ id:string }`
  - 200：`{ code:0, data:{ isRead:true } }`
  - 错误：404（公告不存在）。

## 设计原因与取舍说明
- 类型筛选与置顶拆分：与前端 `FilterBar/useAnnouncements` 保持一致；后端返回统一列表，前端以 `isPinned` 客户端拆分提升复用性。
- `isRead` 与统计：与用户相关，需登录；统计接口可选，亦可由前端基于列表本地计算。
- 统一响应包裹结构与分页约定：复用项目通用处理逻辑，减少前端适配成本。
- 列表使用 `POST`：便于后续扩展复杂筛选（关键词、时间范围）而不破坏接口契约。

## 集成注意事项
- 令牌注入：后端需接受 `Authorization: Bearer`；前端在全局初始化处注入。
- CORS：允许站点前端域；`credentials` 可关闭。
- 速率限制：对 `mark-read` 建议加入 429 防刷；统计接口可做聚合缓存。
- 排序与索引：为 `publishDate/isPinned` 建索引以优化查询；`views/comments` 建议异步更新。

## 与前端字段映射示例
- `src/pages/Announcements/components/FilterBar.tsx`
  - `value('all'|'system'|'event'|'rule'|'maintenance')` → `/announcements/list` 的 `type`。
- `src/pages/Announcements/hooks/useAnnouncements.ts`
  - `filteredAnnouncements` ← `/announcements/list` 的 `items`；前端再拆分 `pinned/normal`。
- `src/pages/Announcements/components/AnnouncementCard.tsx`
  - 展示字段一一对应 `Announcement` 模型；`isPinned/isRead` 控制标记显示。
- `src/pages/Announcements/components/AnnouncementDetail.tsx`
  - 详情数据来源 `/announcements/detail`；点击卡片可触发 `onAnnouncementClick(id)` → 建议结合 `/announcements/mark-read`。
- `src/pages/Announcements/components/StatsSidebar.tsx`
  - 统计口径：总数、未读、置顶；可直接基于列表本地计算，或调用 `/announcements/stats`。
