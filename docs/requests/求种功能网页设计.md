# 求种功能网页设计

## 设计目标
- 基于《求种功能蓝图》，在前端层面明确页面结构、功能与交互，指导实施“发布→认领→提交→验证→结算/仲裁→归档”的闭环。
- 保障权限与状态机一致性、良好的用户体验与可观测性，支持移动端与无障碍。

## 现有页面需改动/优化（RequestsPage）
- 路由参考：`src/routes/AppRoutes.tsx:266-269`，页面主体：`src/pages/RequestsPage.tsx:63`
- 改动方向：
  - 数据源：移除静态假数据，接入接口（列表/详情）与 React Query 缓存；支持筛选、排序、搜索。
  - 视图结构：保留 `list/create/detail` 三视图框架，拆分子组件提升可维护性。
  - 校验增强：发布表单增加悬赏范围/整数校验、分类合法性校验、描述长度与敏感词提示；前端风控文案（冷却期、信誉门槛）。
  - 交互提示：统一成功/失败 Toast、错误重试、操作前确认对话框（取消、加价、仲裁）。
  - 状态可视化：在列表卡片与详情中展示状态徽章、悬赏冻结状态、时间线（创建/认领/提交/验证/结算/到期/仲裁）。
  - 权限显隐：依据后端 `permissions` 控制按钮显隐与禁用（认领/提交/验收/加价/取消/争议）。
  - 性能与体验：Skeleton/Spinner、分页与无限滚动、虚拟列表（高数据量时）、避免重复刷新（`refetchOnWindowFocus=false` 已配置）。
  - 移动端适配：列表卡片栅格→单列堆叠、过滤器折叠、吸顶操作栏。
  - 无障碍：键盘可达 Tab 序、ARIA 标签、可视焦点、文本对比度与可读性。

### 问题梳理（含代码定位）
- 静态数据源：列表与详情依赖本地假数据，缺少真实接口与缓存（`src/pages/RequestsPage.tsx:80-271`）。
- 详情视图非路由化：通过 `view==='detail'` 切换，不能深链接与刷新直达详情（`src/pages/RequestsPage.tsx:501-716`）。
- 事件处理缺失：
  - 发布仅重置表单，无提交与失败提示（`src/pages/RequestsPage.tsx:353-359`）。
  - 评论仅清空输入，无持久化与错误处理（`src/pages/RequestsPage.tsx:361-364`）。
  - 详情操作按钮（投票、我有资源）无逻辑（`src/pages/RequestsPage.tsx:693-710`）。
- 表单校验不足：悬赏未做范围/整数校验，分类合法性与敏感词提示缺失（`src/pages/RequestsPage.tsx:432-446, 448-461`）。
- 状态与时间线薄弱：仅完成状态简要提示，缺少认领/提交/验收/结算节点展示（`src/pages/RequestsPage.tsx:565-576`）。
- 体验与可观测性：无标准化 Loading/Empty/Error、Toast、重试与确认弹窗；移动端与无障碍未系统覆盖。

### 具体落点与改动建议
- 列表点击：由本地 `setSelectedRequest+setView('detail')`（`src/pages/RequestsPage.tsx:834-837`）改为导航 `navigate('/requests/:id')`；保留弹窗为降级。
- 发布与校验：在 `src/pages/RequestsPage.tsx:487-492` 增加悬赏最小值/整数校验、分类合法性、描述长度与敏感词提示；调用 `useCreateRequest` 成功后跳转详情与 Toast。
- 详情操作：在 `src/pages/RequestsPage.tsx:697-707` 绑定 `useVote` 与 `useClaimRequest`，进行中禁用与进度提示；成功后刷新详情。
- 评论发送：替换 `handleSendComment`（`src/pages/RequestsPage.tsx:361-364`）为 `usePostComment`；失败保留输入并提示；评论分页与空态（`src/pages/RequestsPage.tsx:586-621`）。
- 时间线与状态：新增 `RequestTimeline` 展示全流程；右侧信息栏增强到期与冻结状态（`src/pages/RequestsPage.tsx:650-691`）。

## 新增页面与路由
- 求种详情页：`/requests/:id`
  - 功能：详情信息、评论与投票、认领与提交入口、请求者验收、争议入口、事件时间线、订阅按钮。
  - 说明：从列表点击进入，承载完整协作互动；支持分享链接与深链接。
- 我的求种页：`/requests/me`
  - 功能：我发布的求种列表、状态分组（进行中/已完成/已取消/已过期）、快捷操作（加价/取消/订阅设置）。
- 我的应答页：`/requests/claimed`
  - 功能：我认领的求种，进度提醒（待提交/待验证/被拒绝/已完成）、提交入口与历史记录。
- 仲裁台（版主）：`/requests/moderation`
  - 功能：争议列表、详情处理（查看证据、仲裁结果、备注与审计日志）、强制流转（完成/退款/惩罚）。
  - 权限：`review:write` 或 `request:moderate`，与现有 `PermissionRoute` 对齐。

## 页面功能清单（逐页）
- 列表页 `/requests`
  - 过滤与排序：状态、分类、关键字；排序（最新/悬赏/热度）。
  - 列表项：标题、分类徽章、状态、悬赏、投票、评论数、创建者与时间；卡片操作（打开详情、订阅）。
  - 发布区：表单（标题/分类/描述/悬赏），实时校验与提交；成功后跳转详情或返回列表。
  - 空态与错误：无数据/搜索无结果占位；拉取失败重试与错误提示。
- 详情页 `/requests/:id`
  - 信息区：完整描述、悬赏状态（冻结/发放）、当前认领者（如有）、到期时间。
  - 操作区：认领（并发/幂等）、提交资源（`torrentId/externalUrl/proof`）、请求者验收（通过/拒绝）、加价、取消、发起争议、订阅。
  - 协作区：评论列表与发布、投票按钮（防重复投票）、事件时间线（带时间戳和参与者）。
  - 引导：提交成功后的验收引导、验收成功后的结算提示；到期提醒与处理建议。
- 我的求种 `/requests/me`
  - 视图：状态分栏或标签页；支持批量订阅管理。
  - 操作：加价、取消、查看结算记录与账务链接（跳转 Bonus 页）。
- 我的应答 `/requests/claimed`
  - 视图：当前待处理与历史记录；任务进度提示与截止时间。
  - 操作：提交资源、补充证明、查看验收结果与争议信息。
- 仲裁台 `/requests/moderation`
  - 视图：争议队列（可按状态与时间筛选）；详情页处理表单（裁决类型、理由、账务动作预览）。
  - 操作：裁决并触发账务（退款/发放）、记录审计日志；通知双方。
- 订阅管理 `/requests/subscriptions`（可合并到消息中心）
  - 视图：订阅列表、通知偏好；批量操作。

## 路由与权限
- 路由：
  - `/requests` 列表与发布（已存在）
  - `/requests/:id` 详情
  - `/requests/me` 我的求种
  - `/requests/claimed` 我的应答
  - `/requests/moderation` 仲裁台（受保护）
  - `/requests/subscriptions` 订阅管理（可选）
- 权限：
  - 基础 `page:requests`；详情可与基础同权。
  - 动作权限：`request:create/claim/submit/verify/increase_bounty/cancel/dispute`；仲裁 `request:moderate` 或 `review:write`。
  - 显隐策略：后端返回 `permissions`，前端据此控制按钮显隐与禁用。

## 数据流与 Hooks 设计
- API 封装：`src/api/custom/requests.ts`（仿 `bonus.ts`），端点：list/detail/create/claim/link_torrent/verify/increase_bounty/cancel/dispute/comment/vote/subscribe。
- React Query Hooks：
  - `useRequestsList(filters)`：列表查询与分页；支持缓存与刷新。
  - `useRequestDetail(id)`：详情与时间线。
  - `useCreateRequest()`：发布，成功后冻结悬赏与导航。
  - `useClaimRequest(id)`、`useLinkTorrent(id)`、`useVerifyRequest(id)`、`useIncreaseBounty(id)`、`useCancelRequest(id)`、`useDisputeRequest(id)`。
  - `useComments(id)`、`usePostComment(id)`；`useVote(id)`；`useSubscribe(id)`。
- 状态策略：
  - 使用 `QueryProvider` 默认选项（`staleTime=0`、`gcTime=10min`、`retry=1`、`refetchOnWindowFocus=false`）。
  - 乐观更新：投票、评论、订阅等轻量操作可用；提交/验收避免乐观，改为成功提示与重新拉取。

## 组件拆分与复用
- 列表卡片 `RequestCard`：标题、徽章、悬赏、投票数、评论数、状态；点击进入详情。
- 过滤器 `RequestFilters`：状态/分类/搜索/排序；移动端折叠。
- 发布表单 `RequestForm`：字段与校验；错误展示与禁用状态。
- 详情时间线 `RequestTimeline`：事件节点与说明；可展开证据。
- 评论区 `CommentList` + `CommentEditor`：分页加载、富文本或纯文本。
- 操作按钮区 `RequestActions`：认领/提交/验收/加价/取消/争议/订阅；按权限与状态显隐。
- 弹窗 `ClaimDialog`、`SubmitResourceDialog`、`VerifyDialog`、`DisputeDialog`：分离复杂表单与校验。

## 交互与体验规范
- Loading：Skeleton 在列表、Spinner 在详情关键区块。
- Empty：空态插画与引导（新建/修改筛选条件）。
- Error：统一错误边界与重试按钮；重要动作失败弹窗解释与建议。
- 成功与导航：关键动作后 Toast + 主动引导（如提交后提示请求者去验收）。
- 并发控制：认领/提交接口要求幂等键，前端在重复点击时禁用按钮并提示进行中。

## 移动端与无障碍
- 响应式：栅格→单列、吸顶操作与过滤器、弹窗全屏化。
- 触控优化：点击区域扩大、滚动优化、键盘遮挡处理。
- 无障碍：ARIA roles、键盘导航顺序、可视焦点、文案与色彩对比度。

## 指标与埋点
- 行为：发布、认领、提交、验收、加价、取消、争议、订阅、投票、评论。

- 性能：首屏渲染、列表拉取耗时、详情接口耗时、错误率；上报到监控。
