# 工单功能后端对接文档

> 目的：基于前端 `TicketsPage` 及各视图组件的实际数据需求，反向梳理并定义后端接口规范，确保列表、详情、创建、回复、关闭、确认解决、附件上传、统计、管理与指派、我的待办等功能可完整对接。

## 总览与约定
- Base URL：`/api`
- 认证：`Authorization: Bearer <token>`（与 `src/api/core/OpenAPI.ts` 配置一致，统一通过 Bearer Token 注入）
- Content-Type：
  - JSON：`application/json`
  - 上传：`multipart/form-data`
- 时间格式：ISO 8601（示例：`2025-12-10T10:15:30Z`）
- ID 类型：字符串（UUID/雪花）
- 枚举统一：
  - `status`: `pending` | `processing` | `resolved` | `closed`
  - `category`: `technical` | `account` | `resource` | `report` | `other`
  - `priority`: `low` | `normal` | `high` | `urgent`
- 前端请求封装：所有端点当前均为 `POST`（与 `TicketsService` 保持一致），除上传为 `multipart/form-data` 其余走 JSON body。
- 幂等性：创建与回复建议支持 `clientRequestId`（见模型）或请求头 `Idempotency-Key`，后端5分钟窗口内去重。


## 数据模型（与前端类型一致）
- Ticket
  - `id: string`
  - `title: string`
  - `category: category`
  - `status: status`
  - `priority: priority`
  - `createdAt: string`
  - `updatedAt: string`
  - `assignedTo?: string`
  - `messages?: TicketMessage[]`
- TicketMessage
  - `id: string`
  - `author: string`
  - `authorRole: 'user' | 'staff'`
  - `content: string`
  - `timestamp: string`
  - `attachments?: Attachment[]`
- Attachment
  - `attachmentId: string`
  - `url: string`
  - `name: string`
  - `size: number`
  - `uploadedAt?: string`

> 以上模型与 `c:\project\zTorrent-site\src\api\models\CreateAttachmentInput.ts`、`ReplyAttachmentInput.ts` 的字段相匹配，确保前端数组结构可直接回填。

### 获取工单列表
- Path：`POST /api/tickets/list`
- 请求体（`ListTicketsDto` 来自 `c:\project\zTorrent-site\src\api\models\ListTicketsDto.ts`）
```json
{
  "page": 1,
  "pageSize": 20,
  "status": "pending",
  "category": "technical",
  "keyword": "下载速度"
}
```
- 响应（示例）
```json
{
  "code": 1000,
  "message": "OK",
  "data": {
    "page": 1,
    "pageSize": 20,
    "total": 123,
    "items": [
      {
        "id": "TK-2025-0001",
        "title": "下载速度异常缓慢",
        "category": "technical",
        "status": "processing",
        "priority": "high",
        "createdAt": "2025-12-10T08:00:00Z",
        "updatedAt": "2025-12-10T09:00:00Z",
        "assignedTo": "TechSupport",
        "messagesCount": 4
      }
    ]
  },
  "timestamp": "2025-12-10T10:15:30Z",
  "path": "/api/tickets/list"
}
```
- 说明与原因：
  - 前端列表筛选项包含状态、分类与关键词搜索（见 `MyTicketsView`、`TicketManagementView`），响应需提供 `total` 与 `items`。
  - 管理页需展示 `assignedTo` 与 `messagesCount`，建议列表项添加这两个字段以减少二次查询。
- 错误：`400` 分页非法、枚举非法；`401`；`500`

### 上传附件
- Path：`POST /api/tickets/attachments/upload`
- 表单（`UploadAttachmentDto` 来自 `c:\project\zTorrent-site\src\api\models\UploadAttachmentDto.ts`）
  - 字段：
    - `ticketId`（可选，回复场景）
    - `purpose`：`create` | `reply`
    - `file`：二进制文件（此字段虽未在 DTO 中显式声明，但 `core/request.ts` 会将 `formData` 中的键作为 `multipart` 进行拼装，后端需接收 `file`）
- 响应（示例）
```json
{
  "code": 1000,
  "message": "OK",
  "data": { "attachmentId": "ATT-2025-0001", "url": "https://.../att.pdf", "name": "att.pdf", "size": 98765 },
  "timestamp": "...",
  "path": "/api/tickets/attachments/upload"
}
```
- 约束：≤10MB，类型白名单，安全扫描
- 说明与原因：
  - 详情与创建页均有“添加附件”入口（见 `TicketDetailView`、`CreateTicketView`），需统一上传端点。

## 权限与安全
- 访问范围：
  - 普通用户：仅能访问自己创建或被授权可见的工单与消息。
  - 管理/支持组：可访问全部或所辖范围工单，并可执行分配与状态变更。
- 操作审计：创建、回复、分配、状态变更均记录操作者、时间与详情。
- 速率限制：建议按用户与端点维度限流（如 60 req/min）。
- CORS：允许前端域名；上传接口需额外校验来源。

## 设计理由与改动说明（逐项）
- 列表与详情：直接对齐现有 `TicketsService` 和 DTO，以减少前端改动成本。
- 统计数据：前端已有复杂可视化（分类、人员、趋势），因此扩展 `stats` 响应结构，避免多端点聚合带来的复杂度。
- 附件上传：保留统一上传端点；明确 `file` 字段为二进制文件，兼容当前 `multipart/form-data` 实现。
- 分配与标记为已解决：来源于 UI 的操作按钮（管理与详情），目前前端仅日志输出，后端需提供对应端点；与状态机一致。
- 我的待办：来源于 UI 卡片展示的字段需求，定义专用端点避免在列表端做过度复杂的筛选与映射。
- `ListTicketsDto` 扩展或新增管理员列表端点：为满足“按指派”筛选，避免影响普通列表的接口稳定性。
