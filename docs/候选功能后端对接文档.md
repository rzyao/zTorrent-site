# 候选功能后端对接文档

## 目标与范围
- 基于 `src/pages/Candidates` 及其子组件，反向分析前端数据需求，设计候选资源（Candidate）的后端 API 规格，覆盖接口列表、参数、响应示例、错误码、鉴权、分页与筛选与计算规则。
- 设计遵循项目既有规范：统一响应包裹结构、列表查询采用 `POST + JSON Body`、受保护接口支持 `Authorization: Bearer {token}`。
- 不做旧代码兼容；以当前 UI 行为为准，补齐必要的后端能力。

## 前端代码关联
- 页面与装配
  - `src/pages/Candidates/index.tsx`：页面容器与选项卡，筛选逻辑见 `filteredCandidates`（`hall | mySubmissions | myVotes`）。参考：`src/pages/Candidates/index.tsx:196`。
- 组件与字段
  - 创建弹窗：`src/pages/Candidates/components/CreateCandidateModal.tsx` 表单字段包含 `title/type/year/category/quality/description/mediainfo/poster` 等。参考：`src/pages/Candidates/components/CreateCandidateModal.tsx:16`。
  - 详情弹窗：`src/pages/Candidates/components/CandidateDetailModal.tsx` 展示 `status/votesUp/votesDown/deadline/mediainfo/uploaderStats/publishedTorrentId` 等；投票按钮映射“支持/反对”。
  - 计算函数：`getVotePercentage`，规则见下文。参考：`src/pages/Candidates/utils.ts:16`。
  - 类型定义：`src/pages/Candidates/types.ts` 为 Candidate 字段来源。

## 统一鉴权
- 认证：所有受保护接口需 `Authorization: Bearer {token}`（JWT）。
- 权限：
  - 列表大厅（`tab=hall`）与详情可匿名访问。
  - 我的提交（`tab=mySubmissions`）与我的投票（`tab=myVotes`）需登录（后端依据令牌识别用户）。
  - 创建候选与投票需登录；`submittedBy` 由令牌绑定为当前用户。


## 分页与筛选约定
- 列表请求统一采用 `POST + JSON Body`，字段：
  - `page`(默认1)、`pageSize`(默认20，最大100)
  - `tab`(默认`hall`，枚举：`hall | mySubmissions | myVotes`)
  - `sortBy`(默认`submittedAt`，枚举：`submittedAt | votesUp | votesDown | views | comments | deadline | votePercentage`)
  - `sortOrder`(默认`desc`，枚举：`asc | desc`)
- 列表响应统一：`data: { items: Candidate[], total: number }`。
- 过滤逻辑与前端一致：
  - `hall`：仅返回 `status='voting'` 的候选（候选大厅）。
  - `mySubmissions`：当前用户提交的候选。
  - `myVotes`：当前用户参与投票的候选（后端据投票记录反查）。

## 数据模型
- Candidate（候选资源）
  - `id`(string, 只读)：候选资源唯一 ID（建议 UUIDv4/ULID）。
  - `title`(string, 必填)：中文标题。
  - `type`(string, 必填)：英文标题/原名。
  - `year`(string, 必填)：年份（如 `2024`）。
  - `poster`(string, 必填)：海报 URL。
  - `category`(string, 必填)：分类（如“动作/科幻/剧情/喜剧”）。
  - `quality`(string, 必填)：质量参数（如 `4K UHD BluRay HEVC`）。
  - `description`(string, 必填)：资源描述。
  - `mediainfo`(string, 必填)：原始 MediaInfo 文本（可多行）。
  - `submittedBy`(string, 只读)：提交者用户名（令牌映射）。
  - `submittedAt`(string, 只读)：提交时间（ISO 8601）。
  - `status`(`'voting'|'approved'|'rejected'`, 只读, 默认 `'voting'`)：候选状态。
  - `votesUp`(number, 只读, 默认0)：支持票数。
  - `votesDown`(number, 只读, 默认0)：反对票数。
  - `views`(number, 只读, 默认0)：浏览次数。
  - `comments`(number, 只读, 默认0)：评论数。
  - `deadline`(string, 只读)：投票截止时间（ISO 8601，建议默认提交后 24h）。
  - `reason`(string, 只读, 可选)：驳回原因（当 `status='rejected'`）。
  - `requiredVotePercentage`(number, 只读, 可选, 默认 70)：通过所需支持率阈值（百分比）。
  - `fileSize`(string, 可选)：文件总大小（如 `85.6 GB`）。
  - `fileCount`(number, 可选)：文件数。
  - `seeders`(number, 只读)：做种数（通过后可能有值）。
  - `leechers`(number, 只读)：下载数。
  - `uploaderStats`(object, 只读, 可选)：上传者统计 `{ uploads:number, ratio:number, reputation:number }`。
  - `screenshots`(string[], 可选)：截图 URL 列表。
  - `resolution`(string, 可选)：分辨率（如 `3840x2160`）。
  - `videoCodec`(string, 可选)：视频编码（如 `HEVC`）。
  - `audioCodec`(string, 可选)：音频编码（如 `DTS-HD MA 7.1`）。
  - `publishedTorrentId`(string, 只读, 可选)：自动发布后生成的正式种子 ID（当 `approved`）。

## 计算规则
- 支持率（`votePercentage`）
  - 总票数 `total = votesUp + votesDown`；当 `total = 0` 时支持率为 `0`。
  - 计算：`votePercentage = round(votesUp / total * 100)`。
  - 前端实现参考：`src/pages/Candidates/utils.ts:16`。

## 接口列表

### 候选列表
- POST `/candidates/list`
  - 描述：分页检索候选资源列表，支持选项卡过滤与排序。
  - Headers：允许匿名；当 `tab=mySubmissions | myVotes` 需 `Authorization`。
  - Body：`{ page?:number, pageSize?:number, tab?:'hall'|'mySubmissions'|'myVotes', sortBy?:string, sortOrder?:'asc'|'desc' }`
  - 200：`{ code:0, message:'OK', data:{ items: Candidate[], total:number }, path, timestamp }`
  - 备注：`tab=hall` 强制 `status='voting'`；`tab=myVotes` 需根据当前用户投票记录返回其投过票的候选。

### 候选详情
- POST `/candidates/detail`
  - 描述：获取候选详情。
  - Body：`{ id:string }`
  - 200：`{ code:0, data: Candidate }`
  - 404：候选不存在。

### 创建候选
- POST `/candidates/create`
  - 描述：提交候选资源并启动投票截止时间（建议默认 24h）。
  - 权限：需 `Authorization`。
  - Headers（推荐）：`Idempotency-Key: <uuid>` 用于防重复创建。
  - Body（最小字段集，与创建弹窗一致）：
    - `title`(string)，`type`(string)，`year`(string)
    - `category`(string)，`quality`(string)
    - `description`(string)，`mediainfo`(string)
    - `poster`(string)
    - 可选：`resolution`、`videoCodec`、`audioCodec`、`screenshots`、`fileSize`、`fileCount`
  - 校验建议：title 3-100 字；description 10-5000 字；year 4 位数字字符串；URL 合法性；mediainfo 非空。
  - 201/200：`{ code:0, data: Candidate }`（包含后端生成的 `id/submittedBy/submittedAt/status='voting'/deadline/votesUp=0/votesDown=0`）。
  - 409：重复创建（同一用户，同标题+年份+质量）。

### 投票
- POST `/candidates/vote`
  - 描述：对候选资源投票；重复点击同类视为“取消投票”。
  - 权限：需 `Authorization`。
  - Body：`{ id:string, vote:'up'|'down' }`
  - 幂等与行为：
    - 若用户当前无投票，则记录为 `up` 或 `down`。
    - 若用户当前投票与本次相同，则取消投票（删除该用户在该候选的投票记录）。
    - 若不同，则切换投票（例如从 `down` 改为 `up`）。
    - 同一用户对同一候选相同投票重复提交为幂等（不重复累计）。
  - 200：`{ code:0, data:{ candidateId:string, userVote:'up'|'down'|null, votesUp:number, votesDown:number, votePercentage:number } }`
  - 404：候选不存在；403：无权限。

## 设计原因与取舍说明
- 列表采用 `POST + JSON Body`：与项目既有文档一致，便于复杂筛选扩展与统一请求处理。
- 统一响应包裹结构：便于前端通用拦截与错误展示，减少各接口定制差异。
- 投票幂等等价“再次点击同类即取消”：映射前端 `handleVote` 行为，避免重复累计。
- `votePercentage` 服务端计算并返还：前端需要排序与展示；计算规则与前端一致。
- 仅保留页面使用的字段：避免过度设计；对未来字段建议走 `extras` 扩展容器。

## 集成注意事项
- 令牌注入：后端需接受 `Authorization: Bearer` 令牌；前端全局注入。
- CORS：允许前端域；必要时关闭 `credentials`。
- 速率限制：对“投票/创建”接口建议加入 429 防刷。
- 校验与错误：对 `create` 进行后端字段校验，返回 422 字段级错误；重复创建返回 409。
- 排序与索引：为 `submittedAt/votesUp/votesDown/views/comments/deadline` 建索引以优化排序与过滤。
- 截止时间：默认提交后 24h，可在配置中调整。

## 与前端字段映射示例
- 选项卡过滤（`src/pages/Candidates/index.tsx`）
  - `hall` → `/candidates/list` 强制 `status='voting'`。
  - `mySubmissions` → 当前用户 `submittedBy`。
  - `myVotes` → 当前用户投票记录反查候选。
- 创建候选（`CreateCandidateModal.tsx`）
  - 表单字段：`title/type/year/category/quality/description/mediainfo/poster` → `/candidates/create` 最小集；其余技术字段可选填或由后端解析 `mediainfo` 提取。
- 详情弹窗（`CandidateDetailModal.tsx`）
  - 展示字段：`status/votesUp/votesDown/deadline/mediainfo/uploaderStats/publishedTorrentId` → `/candidates/detail` 直接支持；投票按钮 → `/candidates/vote`。

> 如需生成 OpenAPI/Swagger，可按本规范将路径、枚举与响应包裹结构录入，模块分为 Candidates（列表/详情/创建/投票）。
