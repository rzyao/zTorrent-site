# 路由管理系统重构产品需求文档 (PRD)

## 1. 项目背景与目标 (Background & Goals)

### 1.1 背景

当前系统的路由配置呈现出“大一统”的树形结构，`/admin` (管理后台) 被作为 `/app` (前台应用) 的子节点嵌套管理。随着 `/forum` (论坛) 模块的加入，现有的单体树形管理界面变得臃肿且层级混乱，难以高效地进行模块化维护。

### 1.2 核心目标

1.  **架构解耦**：将 Admin, App, Forum 三大业务域在管理层面解耦，消除不合理的父子嵌套关系。
2.  **视窗分治**：通过 UI 分舱设计，让管理员一次只专注于一个业务域的路由配置。
3.  **体验升级**：优化拖拽排序和层级调整的交互逻辑，防止跨业务域的错误操作。

---

## 2. 核心概念 (Core Concepts)

- **三态架构 (Tri-State Architecture)**：系统明确划分为三个顶级业务域：
  - **App (前台)**：面向普通用户的核心产品功能。
  - **Admin (后台)**：面向管理员的系统配置与数据管理功能。
  - **Forum (论坛)**：面向社区用户的讨论与互动功能。
- **Layout 聚合**：使用路由配置中的 `layout` 字段作为业务域的唯一划分依据。

---

## 3. 功能需求 (Functional Requirements)

### 3.1 视图重构 (View Restructuring) [P0]

**需求描述**：
将 `/admin/system/routes` 页面从单一的树形视图重构为 **Tabs 选项卡** 布局。

**详细规则**：

1.  **Tabs 设计**：
    - 页面顶部设置三个固定标签：`[前台应用 (App)]`, `[管理后台 (Admin)]`, `[论坛社区 (Forum)]`。
    - 默认选中 `前台应用 (App)` 或即上次操作的 Tab。
2.  **数据过滤 (Data Filtering)**：
    - 前端获取全量路由数据后，不再渲染为一棵大树。
    - 根据 `layout` 字段或 `path` 前缀将这三部分数据分别渲染到对应的 Tab 面板中。
    - **Admin 特殊处理**：在前端逻辑中，将 `/admin` 节点提升为顶级节点，不再显示为 `/app` 的子节点。

### 3.2 路由树管理 (Route Tree Management) [P0]

**需求描述**：
每个 Tab 面板内部署独立的 `RouteTree` 组件实例。

**详细规则**：

1.  **独立上下文**：
    - 在 "App" Tab 下，只能看到属于 `layout: 'app'` 的路由。
    - 在 "Admin" Tab 下，只能看到属于 `layout: 'admin'` 的路由。
2.  **新建/编辑增强**：
    - **新建路由**：点击“新建”按钮时，自动根据当前激活的 Tab 预填充 `layout` 字段（例如在 Admin Tab 点击新建，默认 `layout = 'admin'`）。
    - **路径前缀**：在 Admin/Forum Tab 下新建路由时，自动建议或校验对应的 path 前缀（`/admin/...` 或 `/forum/...`）。

### 3.3 交互逻辑限制 (Interaction Constraints) [P1]

**需求描述**：
通过交互限制防止业务逻辑错误。

**详细规则**：

1.  **拖拽沙箱**：
    - 禁止节点跨 Tab 拖拽（物理上已隔离）。
    - 在同一 Tab 内，保持现有的拖拽排序和层级调整功能。
2.  **根节点保护**：
    - 各业务域的根节点（如 `/admin` 根路径）应锁定或给予特殊标识，防止被误删除或误移动。

### 3.4 状态与底层逻辑 (State & Logic) [P1]

**需求描述**：
保持底层数据结构的一致性，仅在展现层做切片。

**详细规则**：

1.  **数据一致性**：保存时，依然通过 `UpdateRouteDto` 提交标准数据，后端无需感知前端的 Tab 划分（仅依赖 `layout` 字段）。
2.  **路由匹配**：前端 React Router 依然注册全量扁平路由表，确保 url 跳转逻辑不变。

---

## 4. 非功能需求 (Non-functional Requirements)

1.  **性能要求**：Tabs 切换应无感延迟（< 100ms），建议在初次加载时并行处理数据分组。
2.  **可用性**：即使某个业务域没有数据，也应显示空状态提示，而不是隐藏 Tab。
