# 求种功能后端对接文档

## 目标与范围
- 基于 `src/pages/Requests` 下的页面与组件，反向分析前端数据需求，设计完整后端 API 规格，覆盖接口列表、参数、响应示例、错误码、鉴权、分页与筛选。
- 设计遵循项目既有 OpenAPI/axios 风格：统一响应包裹结构、POST + JSON 作为列表查询的主方式、支持 `Authorization: Bearer {token}`。
- 不做旧代码兼容；以当前 UI 行为为准，补齐所有必要的后端能力。

## 前端代码关联
- 页面容器与选项卡
  - `src/pages/Requests/index.tsx`：装配 Tabs 与内容区。
  - `src/pages/Requests/hooks/useRequestsTabs.ts`：Tab 枚举 `hall | my-requests | my-responses | moderation | create`，管理员可见 `moderation`。
- 求种大厅与筛选
  - `src/pages/Requests/components/RequestsHall.tsx`：筛选项 `keyword`、`category`、`status(all|active|completed|expired)`、`sortBy(latest|bounty|comments|votes)`；卡片字段包含 `title/description/category/bounty/additionalBounty/status/createdAt/deadline/author/commentsCount/votesCount/claimedBy`。
- 我的求种
  - `src/pages/Requests/components/MyRequests.tsx`：状态分组 `ongoing(draft|active)` 与 `history(completed|cancelled|expired)`；操作含“发布/取消/追加/删除草稿/重新发布/去验收”等；字段含 `pendingSubmissions`。
- 我的应答
  - `src/pages/Requests/components/MyResponses.tsx`：状态筛选 `claimed|submitted|approved|rejected|disputed`；操作含“提交资源/放弃/重新提交/发起仲裁/补充证据”等。
- 仲裁中心
  - `src/pages/Requests/components/ModerationCenter.tsx`：仲裁案件字段 `requestTitle/category/bounty/requester/responder/timeline/evidence(priority)`；动作：“通过验收/拒绝验收/处罚违规方/请求更多证据”。
- 求种详情
  - `src/pages/Requests/components/RequestDetail.tsx`：整体状态 `active|claimed|submitted|completed|disputed`；时间线事件 `created|claimed|submitted|approved|rejected|disputed|bounty_added`；评论与附件；操作随角色变化（访客/发布者/认领者）。

## 统一鉴权
- 认证：所有受保护接口需 `Authorization: Bearer {token}`；令牌由前端通过本地存储注入。
- 权限：
  - 基础访问：`page:requests`（对应路由守卫）。
  - 发布求种：`requests:create`。
  - 认领/提交：`requests:claim`、`requests:submit`。
  - 验收/拒绝：`requests:review`（发布者）。
  - 仲裁操作（管理员）：`requests:moderate` 或角色 `admin`。

## 统一错误与响应格式
- 统一包裹：
  - 成功：`{ code: 0, message: 'OK', data: <payload>, path: <string>, timestamp: <ISO> }`
  - 失败：`{ code: <httpStatus|appCode>, message: <string>, data?: <optional>, path, timestamp }`
- 标准错误码：
  - 400 参数错误；401 未认证；403 禁止访问；404 资源不存在；500 服务器错误。
  - 建议扩展：409 冲突（如重复认领）、422 校验失败（字段级错误）、429 频率限制。

## 分页与筛选约定
- 列表请求统一采用 POST + JSON Body，字段：
  - `page`(默认1)、`pageSize`(默认20，最大100)、`keyword`(可选)、`category`(可选)、`status`(枚举)、`sortBy`(枚举)。
- 列表响应统一：`data: { items: any[], total: number }`。
- 排序枚举（大厅）：`latest|bounty|comments|votes`；约定排序二级键：`createdAt`、`(bounty+additionalBounty)`、`commentsCount`、`votesCount`。

## 数据模型
- Request（求种）
  - `id`(string)、`title`(string)、`category`(enum: 电影|剧集|纪录片|音乐|动漫|综艺|体育|其他)、`description`(string)、`bounty`(number, >=100)、`additionalBounty`(number, >=0)、`totalBounty`(number, 只读)、`status`(enum: draft|active|claimed|submitted|completed|cancelled|expired|disputed)、`createdAt`(ISO)、`deadlineAt`(ISO)、`author`({id,name,level?})、`counts`({comments:number,votes:number,views:number})、`claimedBy`({id,name}? )、`attachments`(string[] URL)。
- Submission（应答/资源提交）
  - `id`、`requestId`、`responder`({id,name})、`status`(claimed|submitted|approved|rejected|disputed)、`claimedAt`、`submittedAt?`、`rejectionReason?`、`resource`({title?,link?,torrentId?,mediaInfoImages?:string[]})。
- DisputeCase（仲裁）
  - `id`、`requestId`、`requestTitle`、`category`、`bounty`、`requester`、`responder`、`timeline`({claimedAt,submittedAt,rejectedAt,disputeCreatedAt})、`statements`({requesterStatement,responderStatement})、`submittedResource`(string)、`chatHistory`(string[])、`evidence`([{type:'image'|'file'|'text',content:string,uploader:'requester'|'responder'}])、`priority`('low'|'medium'|'high')、`status`('open'|'resolved')。
- Comment
  - `id`、`requestId`、`author`({id,name,avatar?})、`content`(string)、`createdAt`。
- TimelineEvent
  - `id`、`type`('created'|'claimed'|'submitted'|'approved'|'rejected'|'disputed'|'bounty_added')、`user`({id,name})、`description`(string)、`timestamp`。

## 接口列表（按功能模块）

### 求种大厅
- POST `/requests/list`
  - 描述：分页检索大厅列表，支持关键词、分类、状态与排序。
  - Headers：`Authorization: Bearer {token}`。
  - Body：`{ page?:number, pageSize?:number, keyword?:string, category?:string, status?:'active'|'completed'|'expired'|'all', sortBy?:'latest'|'bounty'|'comments'|'votes' }`
  - 200：`{ code:0, message:'OK', data:{ items: Request[], total:number }, path, timestamp }`
  - 错误：400/401/403/500。
- POST `/requests/detail`
  - 描述：获取求种详情（含计数、附件、认领信息、时间线摘要）。
  - Body：`{ id:string }`
  - 200：`{ code:0, data: Request & { timeline: TimelineEvent[] } }`
  - 错误：404（不存在）。

### 发布与编辑
- POST `/requests/create`
  - 描述：创建求种并冻结悬赏积分。
  - 权限：`requests:create`。
  - Body：`{ title:string, category:string, description:string, bounty:number, deadlineDays:3|7|14|30, attachments?:string[] }`
  - 校验：title 3-100 字；description 10-5000 字；bounty>=100；category 取枚举。
  - 200：`{ code:0, data:{ id:string } }`
- POST `/requests/save-draft`
  - 描述：保存草稿，不冻结积分。
  - Body：同 `create`，允许缺项；`status` 固定为 `draft`。
  - 200：`{ code:0, data:{ id:string } }`
- POST `/requests/update`
  - 描述：更新草稿或进行中求种（禁止直接变更已完成/取消）。
  - Body：`{ id:string, title?, category?, description?, attachments? }`
  - 200：`{ code:0, data:{} }`
- POST `/requests/publish`
  - 描述：将草稿发布为 `active`，冻结悬赏。
  - Body：`{ id:string }`
  - 200：`{ code:0, data:{} }`
- POST `/requests/cancel`
  - 描述：发布者取消进行中求种；退款逻辑按规则退回。
  - Body：`{ id:string, reason?:string }`
  - 200：`{ code:0, data:{} }`
- POST `/requests/republish`
  - 描述：将 `expired|cancelled` 重新发布为新任务（或重置时钟）。
  - Body：`{ id:string, deadlineDays?:3|7|14|30 }`
  - 200：`{ code:0, data:{ newId?:string } }`

### 悬赏与资金
- POST `/requests/add-bounty`
  - 描述：追加悬赏（可由他人或发布者追加）。
  - Body：`{ id:string, amount:number }`
  - 200：`{ code:0, data:{ totalBounty:number, additionalBounty:number } }`

### 认领与提交（应答方）
- POST `/requests/claim`
  - 描述：认领任务；若已被认领返回 409。
  - 权限：`requests:claim`。
  - Body：`{ id:string }`
  - 200：`{ code:0, data:{ claimId:string } }`
- POST `/requests/abandon`
  - 描述：应答方放弃任务。
  - Body：`{ claimId:string, reason?:string }`
  - 200：`{ code:0, data:{} }`
- POST `/requests/submit`
  - 描述：提交资源等待验收。
  - 权限：`requests:submit`。
  - Body：`{ claimId:string, resource:{ title?:string, link?:string, torrentId?:string, mediaInfoImages?:string[] }, note?:string }`
  - 200：`{ code:0, data:{ submissionId:string } }`
- POST `/requests/resubmit`
  - 描述：被拒后重新提交。
  - Body：`{ submissionId:string, resource:{...}, note?:string }`
  - 200：`{ code:0, data:{} }`

### 验收（发布者）
- POST `/requests/approve-submission`
  - 描述：通过验收并发放悬赏。
  - 权限：`requests:review`。
  - Body：`{ submissionId:string }`
  - 200：`{ code:0, data:{ paid:boolean } }`
- POST `/requests/reject-submission`
  - 描述：拒绝验收并附原因。
  - Body：`{ submissionId:string, reason:string }`
  - 200：`{ code:0, data:{} }`
- POST `/requests/pending-submissions`
  - 描述：查询某发布者待验收计数。
  - Body：`{ requesterId?:string }`
  - 200：`{ code:0, data:{ count:number } }`

### 我的求种/我的应答
- POST `/requests/my/list`
  - 描述：列表当前用户的求种，支持分组筛选。
  - Body：`{ page?:number, pageSize?:number, group?:'ongoing'|'history' }`
  - 200：`{ code:0, data:{ items: Request[], total:number } }`
- POST `/requests/my-responses/list`
  - 描述：列表当前用户的应答任务。
  - Body：`{ page?:number, pageSize?:number, status?:'claimed'|'submitted'|'approved'|'rejected'|'disputed'|'all' }`
  - 200：`{ code:0, data:{ items: Submission[], total:number } }`

### 评论与投票
- POST `/requests/comments/list`
  - 描述：获取评论列表。
  - Body：`{ requestId:string, page?:number, pageSize?:number }`
  - 200：`{ code:0, data:{ items: Comment[], total:number } }`
- POST `/requests/comments/create`
  - 描述：发表新评论。
  - Body：`{ requestId:string, content:string }`
  - 200：`{ code:0, data:{ id:string } }`
- POST `/requests/votes/upvote`
  - 描述：为求种“投票/点赞”；幂等。
  - Body：`{ requestId:string }`
  - 200：`{ code:0, data:{ votesCount:number } }`

### 附件上传
- 复用现有图片上传服务：`POST /images/upload`
  - Body：`{ content:string(base64|dataURL), filename:string, mimeType?:string }`
  - 200：`{ code:0, data:{ url:string } }`

### 仲裁中心（管理员）
- POST `/requests/disputes/list`
  - 描述：分页列出争议案件，支持优先级筛选。
  - 权限：`requests:moderate` 或 `admin`。
  - Body：`{ page?:number, pageSize?:number, priority?:'high'|'medium'|'low'|'all', status?:'open'|'resolved'|'all' }`
  - 200：`{ code:0, data:{ items: DisputeCase[], total:number } }`
- POST `/requests/disputes/detail`
  - 描述：获取案件详情。
  - Body：`{ id:string }`
  - 200：`{ code:0, data: DisputeCase }`
- POST `/requests/disputes/decide`
  - 描述：裁决案件（通过验收/拒绝验收/处罚）。
  - Body：`{ id:string, decision:'approve'|'reject'|'punish', reason?:string }`
  - 200：`{ code:0, data:{ status:'resolved' } }`
- POST `/requests/disputes/request-evidence`
  - 描述：向双方请求更多证据。
  - Body：`{ id:string, note?:string }`
  - 200：`{ code:0, data:{} }`

## 设计原因与取舍说明
- 使用 POST + JSON 进行列表检索：与现有服务保持一致，便于复杂筛选与扩展字段。
- 统一响应包裹结构：`{code,message,data,path,timestamp}`，便于前端通用处理与错误拦截。
- 列表响应 `items+total`：匹配分页组件使用习惯，直接可用。
- 状态枚举扩展：将 `claimed|submitted|disputed` 纳入整体状态，满足详情页状态展示。
- 追加悬赏独立接口：前端存在“追加悬赏”动作，分离资金操作便于权限与审计。
- 认领/提交/验收分离：映射“我的应答”与发布者验收动作，职责清晰。
- 仲裁接口模块化：满足管理员“裁决/请求证据/处罚”操作，支持优先级筛选。
- 附件上传复用既有图片服务：避免重复实现文件上传，简化对接。

## 集成注意事项
- 令牌注入：后端需接受 `Authorization: Bearer`；前端在全局初始化处设置。
- CORS：允许站点前端域；`credentials` 可关闭。
- 速率限制：对“发表评论/投票/追加悬赏/认领”等接口建议加入 429 防刷。
- 校验与错误：对 `create`/`submit` 进行后端字段校验，返回 422 字段级错误；认领冲突返回 409。
- 排序与索引：为 `createdAt`、`totalBounty`、`commentsCount`、`votesCount` 建索引以优化排序。
- 时间线生成：服务端写入事件，供详情页展示；追加悬赏/认领/提交/验收/拒绝/仲裁均落事件。
- 计数维护：`commentsCount/votesCount/viewsCount/pendingSubmissions` 建议异步更新以避免写放大。

## 与前端字段映射示例
- 大厅筛选与排序（`src/pages/Requests/components/RequestsHall.tsx`）
  - 需求字段：`searchQuery/sortBy/statusFilter/categoryFilter` → `/requests/list` 的 `keyword/sortBy/status/category`。
  - 卡片展示字段：`bounty/additionalBounty/commentsCount/votesCount/claimedBy` → `Request` 模型直接支持。
- 我的求种（`MyRequests.tsx`）
  - 分组：`ongoing|history` → `/requests/my/list` 的 `group`。
  - 操作：“发布/取消/追加/删除草稿/重新发布/去验收” → `/requests/publish`、`/requests/cancel`、`/requests/add-bounty`、`/requests/save-draft`、`/requests/republish`、`/requests/pending-submissions`。
- 我的应答（`MyResponses.tsx`）
  - 状态：`claimed|submitted|approved|rejected|disputed` → `/requests/my-responses/list` 的 `status`。
  - 操作：“提交/放弃/重新提交/发起仲裁/补充证据” → `/requests/submit`、`/requests/abandon`、`/requests/resubmit`、`/requests/disputes/create`、`/requests/disputes/request-evidence`。
- 仲裁中心（`ModerationCenter.tsx`）
  - 筛选：`priorityFilter` → `/requests/disputes/list` 的 `priority`。
  - 操作：“通过/拒绝/处罚/请求证据” → `/requests/disputes/decide`、`/requests/disputes/request-evidence`。
- 发布求种（`CreateRequest.tsx`）
  - 表单字段：`title/category/description/bounty/deadline(天数)/attachments` → `/requests/create`；附件先走 `/images/upload`。

> 如需生成 OpenAPI/Swagger，可按本规范将各路径、枚举与响应包裹结构录入，模块化分组为 Requests、Submissions、Disputes、Comments、Votes、Assets。
