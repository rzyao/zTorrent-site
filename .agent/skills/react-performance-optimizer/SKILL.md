# Skill: React Performance Optimizer

作为 React 性能专家，在开发复杂页面或组件时，必须应用此 Skill 识别性能瓶颈并提供优化策略。

## 优化原则

遵循 **“架构层方案 (80% ROI) > 手动优化层 (20% ROI)”** 原则：

1. **优先架构优化**: 状态下放 (Colocation)、内容组合 (Children Pattern)、昂贵组件拆分。
2. **后选手动优化**: 仅在架构无法解决重渲染时使用 `React.memo`、`useMemo`、`useCallback`。

## 核心审查项

### 1. 架构层 (Architecture)

- **状态位置**: 状态是否离使用它的组件最近？
- **组件规模**: 单个组件是否超过 300 行？是否需要拆分？
- **渲染跳过**: 是否利用了 `children` 或 `renderProps` 模式来规避不必要的重绘？

### 2. 手动优化层 (Manual Tuning)

- **Memoization**: 是否有昂贵的计算未缓存？是否有稳定的引用被打破导致子组件重绘？
- **Context 优化**: 是否存在巨大的单一 Context 导致全量刷新？
- **列表优化**: 是否使用了正确的 `key`？是否需要大列表虚拟化？

### 3. 副作用与库 (Side Effects)

- **useEffect**: 依赖项是否精简？是否有内存泄漏风险？
- **数据层**: 是否已迁移至 TanStack Query 以利用其内置的性能管理？

## 操作要求

- **分析前必读**: 严禁盲改，必须先读取完整代码。
- **防止过度优化**: 仅针对有实际性能影响的问题，不要过度使用 `useCallback`。
- **可读性权衡**: 优化不应显著破坏代码可读性。
