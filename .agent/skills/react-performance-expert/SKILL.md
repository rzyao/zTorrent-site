# React 性能优化专家技能 (React Performance Expert)

此技能将 Antigravity 提升为一名 React 性能调优专家。在编写、重构或审查 React 代码时，务必主动应用此技能中的原则。

## 核心原则：成本-收益分层法则 (ROI Layering)

优化必须遵循分层原则：**优先进行架构层优化（ROI 80%），仅在必要时动用手动 Hook 工具（ROI 20%）。**

### 1. 第一层：架构级优化 (Architecture - ROI 80%)

**目标**：通过改变代码结构自然避开性能坑。

- **状态下放 (State Colocation)**：
  - 准则：将状态留在最靠近使用它的组件中。
  - 场景：如果一个页面顶层的状态只被某个深层小组件使用，应将该状态下移。
- **内容组合模式 (Children/Component Injection Pattern)**：
  - 准则：利用 `children` 或作为 Props 传入组件来隔离渲染。
  - 逻辑：父组件重绘时，作为 `children` 传入的组件引用不变，会自动跳过 React 渲染过程。
- **昂贵组件拆分**：
  - 将庞大的组件拆分为“逻辑容器”和“纯展示组件”。
  - 将低频更新且开销大的 UI 块独立出来。

### 2. 第二层：手动优化 Hooks (Hooks - ROI 20%)

**目标**：当架构重构无法解决冗余重渲染时，使用 React 提供的原子化工具。

- **React.memo**：
  - 仅用于渲染开销确实很大的纯展示组件。
  - 配合 `tailwind-merge` 或简单的 Props 比较。
- **useMemo**：
  - 缓存复杂计算（如：大列表排序、聚合统计）。
  - 缓存作为 Props 传递给 `React.memo` 组件的非原始类型数据（对象、数组）。
- **useCallback**：
  - 缓存传递给 `React.memo` 组件的函数引用。
  - 缓存作为 `useEffect` 依赖项的函数。

### 3. 第三层：副作用与外部数据 (Side Effects & Data)

- **TanStack Query 优先**：禁止在组件中手动使用 `useEffect` + `axios`。利用缓存机制减少不必要的网络请求和状态抖动。
- **Context 分片**：不要把所有数据塞进一个 GlobalProvider。按业务领域拆分 Context，或使用 `useMemo` 包装 `value` 对象。

## 性能审查清单 (Expert Checklist)

在阅读或编写代码时，请自问：

1. [ ] **状态范围**：这个状态变更是否导致了 50% 以上无关组件的重渲染？如果是，请应用“状态下放”。
2. [ ] **计算属性**：在 Render 函数内部是否有复杂的过滤/排序操作未被 `useMemo` 包裹？
3. [ ] **函数引用**：传递给子组件的事件 Handler 是否在每次渲染时都是新引用？
4. [ ] **大列表**：超过 50 条数据的列表是否实现了虚拟化 (Virtualization)？

_注：避免过度优化。如果组件很小且渲染频率不高，不要强行加入大量的 useCallback，以免增加维护心智负担。_
