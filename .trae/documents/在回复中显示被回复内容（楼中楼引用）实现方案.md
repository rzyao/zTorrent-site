# 在回复中显示被回复内容（楼中楼引用）实现方案

## 目标
- 在帖子详情页的回复列表中，针对有 `parentId` 的回复显示“被回复内容”的引用块，不再只显示 `@user`。
- 点击“回复”时，编辑框自动预填 `@user` 与引用原文片段，提升上下文清晰度。

## 前端改动（ForumPage.tsx）
- 数据结构与辅助：
  1. 保持 `IForumPost` 的 `parentId?: string | null` 与 `authorUsername?: string`（已存在，不需再改）。
  2. 新增 `useMemo` 构建 `postsMap`：将当前页的 `posts` 转为 `id→回复对象` 的 Map，用于快速查找父回复。
  3. 可选：若后端返回中包含主题正文（详情），将主题正文作为“根回复”加入 Map（id: `thread-root`），便于将回复主题内容作为引用（无 parentId 的情况无需显示）。

- 回复列表渲染：
  1. 在 `posts.map(reply)` 的每项顶部，若 `reply.parentId` 存在：
     - 从 `postsMap` 查找父回复 `parent = postsMap.get(reply.parentId)`。
     - 渲染引用块：显示父回复作者（`authorUsername||authorId`）与父回复内容片段（前 200 字，保留换行），带左侧色条与淡色背景。
     - 若父回复不在当前页（`!parent`），显示占位提示：“引用内容暂不可见（不在当前页）”。
     - 给父回复列表项增加 `id="reply-{parentId}"`，在引用块右上角提供“查看原回复”按钮，点击滚动定位到父回复位置（同页锚点导航）。

- “回复”按钮交互增强：
  1. 现有点击“回复”时已设置 `replyParentId`、预填 `@用户名 ` 并聚焦编辑框。
  2. 增强预填：除 `@用户名 ` 外，追加 Markdown 风格的引用片段：
     - 格式示例：
       ```
       @用户名 
       > 原文片段前 200 字（每行前加 '>'）
       
       ```
     - 通过 `postsMap.get(reply.id)?.content` 取得引用源，逐行转为 `> ...` 并插入编辑框开头，与 `@用户名` 保持一行。

- 发送逻辑：
  1. 保持现有 `parentId: replyParentId || undefined` 提交，后端按 `parentId` 建楼中楼关系。
  2. 成功后刷新列表并清空 `replyParentId`，编辑框清空。

## 视觉与交互细节
- 引用块样式：
  - 左侧 3px 色条（amber），背景 `bg-neutral-900/40`，内容 `text-neutral-300`；顶栏显示 `@用户名` 与“查看原回复”小按钮。
- 当父回复不在当前页：
  - 文案：“引用内容暂不可见（该楼层不在当前页）”；可后续扩展为按 `parentId` 拉取单条回复端点。

## 后端配合（可选优化）
- 建议新增：`GET /forum/posts/get-post?id=<replyId>` 返回单条回复（含作者与内容），便于前端在父回复不在当前页时拉取并显示引用块；当前实现将先做优雅降级不拉取。

## 验证用例
- 点击某条回复的“回复”：编辑框自动插入 `@用户名` + 原文引用；发送后列表展示该新回复，引用块显示父回复内容。
- 父回复在当前页与不在当前页两种情况：
  - 在当前页：引用块显示原文片段与“查看原回复”锚点跳转。
  - 不在当前页：显示“引用内容暂不可见”的提示。
