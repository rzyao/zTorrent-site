# 避免楼中楼重复引用的前端调整方案

## 问题描述
- 当前点击“回复”会在编辑框自动插入：`@用户名` + 原文的 Markdown 引用
- 回复发布后，列表渲染同时显示父回复的“引用块”，与编辑框中的原文引用重复

## 解决思路（保留一种引用展示）
- 统一保留列表渲染的“引用块”，取消编辑框中自动插入原文内容
- 仅在编辑框自动插入 `@用户名`（便于明确回复对象），不插入原文
- 发布后列表继续显示“引用块”（可见父回复内容的片段）

## 具体改动
- 文件：`src/pages/ForumPage.tsx`
- 位置：回复项“回复”按钮点击逻辑（约 660 行）：
  - 移除对原文的 Markdown 处理与插入（`> 原文…`）
  - 保留并插入 `@用户名 `，随后自动焦点到文本域
- 位置：取消“正在回复”逻辑（约 694 行）：
  - 保留取消时清理 `@用户名` 前缀与回复父ID，但不再清理原文引用（因为不再插入）
- 列表渲染不变：继续显示“父回复引用块”，避免重复

## 可选增强（按需）
- 在回复输入区增加“插入原文引用”复选框：
  - 勾选时才向编辑框插入 Markdown 引用
  - 同时在列表渲染中避免重复：当检测到内容以 `>` 开头的引用存在时仅显示其中一种（例如不再显示列表引用块）
- 初版建议先统一去除编辑框原文插入，保证体验清晰

## 验证步骤
- 点击“回复”仅插入 `@用户名`，不出现原文内容
- 发布后列表显示父回复引用块，无二次重复
- 点击“取消”清除回复状态与 `@用户名` 前缀

—— 确认后我将按上述方案修改前端逻辑，去除编辑框中的原文引用插入，仅保留 `@用户名`。
