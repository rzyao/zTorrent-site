## 目标
- 在触发下载时按来源携带 `source`：
  - 从片单→影片→下载：`{ filmId: 'filmId', playListId: 'playListId' }`
  - 从影片页直接下载：`{ filmId: 'filmId', playListId: '' }`
  - 从种子列表/详情下载：`{ filmId: '', playListId: '' }`
- 将 `source` 与下载事件一并上报后端，便于统计分析。

## 现状综述
- 统一下载逻辑在 `src/features/download/useTorrentDownload.ts:31` 的 `downloadByTorrentId(torrentId, name?)`。
- 列表页触发：`src/pages/TorrentsPage.tsx:304` 与 `:343`。
- 详情页触发：`src/pages/TorrentDetailPage/index.tsx:344` 与右键菜单 `:717`。
- 影片页“立即下载”按钮未接入下载逻辑：`src/pages/FilmDetailPage.tsx:271`。
- 生成下载链接：`POST /torrents/download-url`（`src/api/services/TorrentsService.ts:62`），当前仅接收 `{ torrentId }`。
- 记录下载：`POST /torrents/record-download`（`src/api/services/TorrentsService.ts:476`），当前 `RecordDownloadDto` 仅含 `torrentId`（`src/api/models/RecordDownloadDto.ts:9`）。

## 实施思路
- 前端不改后端契约的前提下，使用项目已有的低层请求工具直接 POST 扩展字段（参考片单关注的做法，`src/pages/PlaylistsPage.tsx:70-76`）。
- 在下载 Hook 成功保存文件后，追加一次“下载记录上报”请求，体内带上 `source`。
- 将来源采集标准化：
  - 种子页/种子详情页：空来源 `{ filmId: '', playListId: '' }`。
  - 影片页：从影片模型读取 `filmId`，`playListId` 取路由状态或置空。
  - 片单跳转到影片：通过路由 `state` 传递 `playListId`，影片页下载时合并 `filmId` 与该 `playListId`。

## Hook 扩展（不改后端契约）
- 修改 `useTorrentDownload`：第三参新增可选 `source`；成功后用底层 `request` 直接 POST。
- 代码示例（关键片段）：
```ts
// src/features/download/useTorrentDownload.ts
import { request as apiRequest } from '@/api/core/request';
import { OpenAPI } from '@/api/core/OpenAPI';

export type DownloadSource = { filmId: string; playListId: string };

const downloadByTorrentId = async (
  torrentId: string,
  name?: string,
  source?: DownloadSource,
) => {
  // ...保持生成链接与实际下载逻辑不变
  saveBlobAsFile(blob, filename);
  customToast.success('下载已开始');

  // 记录下载：携带来源（后端可渐进支持该扩展字段）
  try {
    await apiRequest(OpenAPI, {
      method: 'POST',
      url: '/torrents/record-download',
      body: { torrentId, source: {
        filmId: String(source?.filmId ?? ''),
        playListId: String(source?.playListId ?? ''),
      } },
      mediaType: 'application/json',
    });
  } catch (_) {}
};
```
- 说明：不使用 `TorrentsService.torrentsControllerRecordDownload` 是为了绕过类型约束；待后端 OpenAPI 更新新增 `source` 后，再回切到强类型方法。

## 来源采集与传递
- 定义统一帮助函数：
```ts
export const buildSource = (
  filmId?: string,
  playListId?: string,
): DownloadSource => ({
  filmId: String(filmId ?? ''),
  playListId: String(playListId ?? ''),
});
```
- 路由 `state` 用于在“片单 → 影片”链路中传递 `playListId`。

## 验证与回滚
- 验证：
  - 从三处入口分别触发下载，抓包确认 `/torrents/record-download` 请求体带 `source`；
  - 后端未识别 `source` 时不影响下载体验（前端吞错），仅统计缺失。
- 回滚：
  - 如后端明确禁止额外字段，前端降级为仅上报 `{ torrentId }`，同时暂存 `source` 于 `localStorage` 供后续批量上报。
