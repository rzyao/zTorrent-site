## 目标与对接原则
- 目标：将审核页从模拟数据改为真实数据，支持影片/片单/种子三类的待审、已通过、已驳回管理；提供审批操作与历史查看；与后端“审核开关”联动。
- 原则：
  - 列表页（用户端）无需额外参数，后端自动过滤（开关开启时仅返回 `approved`）
  - 审核页（管理端）需要能查询全部/按 `approvalStatus` 过滤，并提供审批动作接口
  - 统一响应兼容两种格式（统一包裹/直返），统一错误码映射与提示

## 实施方案
- 审核页数据源改造（替换模拟数据）
  - 影片：调用“管理员可见”的影片列表接口，要求支持筛选 `approvalStatus`、`keyword`、`uploaderId`、分页；若暂不可用，先以 `list-films` 兜底但只能取 `approved`（用于验证 UI），待后端补充再切换
  - 片单：同影片，调用管理员列表接口；暂不可用则以 `list-playlists` 兜底
  - 种子：优先调用 `torrentsControllerListTorrentsForAdmin`，并补充 `approvalStatus` 过滤与 `approvedAt` 排序（后端若未支持需配合）
  - 统一解包：在 `ReviewPage.tsx` 内封装 `unwrapResponse()`，兼容 `{ code:1000, data }` 与直返体
- 审批操作（通过/驳回）
  - 种子：直接使用 `torrentsControllerUpdate({ id, approvalStatus })` 写入 `approved/rejected`，附带可选 `approvedAt`/`rejectedReason`
  - 影片/片单：需要后端提供更新审批状态的接口；前端在确认模态提交后调用，更新本地列表状态并提示成功
- 审核历史
  - 页面保留“审核历史”模态；后端提供 `GET /audit/history?type&resourceId` 或资源内嵌 `approvalLogs` 字段；前端按统一响应解包渲染时间线
- 过滤与分页
  - 顶部筛选栏支持：类型（film/playlist/torrent）、状态（pending/approved/rejected）、关键词、上传者；分页与统计卡跟随筛选更新
- UI 与权限
  - 将 `/review` 路由改为权限守卫 `PermissionRoute`，仅管理员/有审核权限用户可访问（在 `src/routes/AppRoutes.tsx` 替换守卫）
  - 列表页与详情页保持用户端逻辑不改动；开启审核后自动只见 `approved`
- 审核开关读取
  - 在审核页顶部显示当前开关状态（只读），或在“系统设置”页新增审核开关管理：读取 `film.review`/`playlist.review`/`torrent.review` 并支持批量更新（`SettingsService.settingsControllerUpdateSettingsItems`）

## 详细改动点（逐步落地）

  - 历史：`fetchAuditHistory(item)` 调用后端日志接口或使用资源中的 `approvalLogs`

## 后端配合项（必需/建议）
- 列表（管理端）
  - 影片：提供管理员列表接口（例如 `POST /admin/films/list`），支持 `page, limit, keyword?, uploaderId?, approvalStatus?, approvedAtSort?`
  - 片单：提供管理员列表接口（例如 `POST /admin/playlists/list`），支持同上
  - 种子：在 `POST /torrents/admin/list` 或现有管理员端点上增加 `approvalStatus` 过滤与 `approvedAt` 排序
- 审批动作（管理端）
  - 影片：`POST /admin/films/update-approval` → `{ id, action:'approve'|'reject', reason? }`
  - 片单：`POST /admin/playlists/update-approval` → 同上
  - 种子：若沿用更新端点，则允许传 `approvalStatus` 与 `approvedAt/rejectedReason`；或提供专门审批端点
- 审核历史
  - 通用：`GET /audit/history?type&resourceId` → 返回时间线（操作者、时间、动作、备注）
  - 或在资源详情返回中内嵌 `approvalLogs: AuditLog[]`
- 设置开关
  - 在 `list-setting-by-group` 中加入 `group='review'`，包含 `film.review`、`playlist.review`、`torrent.review`
  - 统一值类型为布尔或可解析布尔的字符串（`'true'|'false'`），保证前端 Switch 显示一致

## 统一响应与错误码处理
- 兼容后端统一响应：页面内统一 `unwrapResponse()` 优先取 `{ code===1000 ? data : throw }`，否则直返体
- 错误码映射：后端 `401→9401` 等已在拦截器与封装层处理；页面只需使用 `extractErrorMessage()` 显示用户友好提示

## 验证方案
- 开关关闭场景：审核页可拉全量（含 `pending/rejected`），用户端列表页显示所有（若后端定义如此）
- 开关开启场景：审核页可拉全量并操作；用户端列表页仅显示 `approved`
- 用示例关键字（如“哈利波特”）验证筛选与分页；操作后验证状态更新与统计卡联动
- 权限验证：未授权用户访问 `/review` 时被阻拦与重定向

## 风险与兼容
- 若影片/片单暂缺审批字段或接口，前端将保留 UI 并仅渲染种子类的真实数据；待后端补齐后切换调用
- 若管理员列表暂未支持 `approvalStatus`，可先按 `approvedAt` 排序显示近似状态区分（仅作为临时权宜）
