## 目标
- 为 `src/pages/forum/RichTextEditor.tsx` 增加“图片上传”功能，支持从本地选择图片文件上传至后端并将返回的 URL 插入编辑器内容。
- 默认使用现有端点 `ImagesService.imagesControllerUpload({ file })`（POST /images/upload, multipart/form-data），与项目其他页面一致。

## 改动点
1) 引入上传服务
- 在组件中导入：`import { ImagesService } from '@/api/services/ImagesService'`。
- 原因：复用已存在、稳定的图片上传端点，避免重复造轮子。

2) 组件能力扩展（保持向后兼容）
- 添加可选新属性：`onUploadImage?: (file: File) => Promise<string>`，用于允许外部注入自定义上传逻辑；默认实现调用 `ImagesService`。
- 原因：提升可扩展性，便于以后切换存储（如 OSS/S3）或做鉴黄/压缩等预处理。

3) 工具栏与交互
- 在现有“插入图片”区块旁新增“上传图片”按钮，点击打开一个选择文件的对话（`<input type="file" accept="image/*">`），也可复用现有模态框样式展示上传状态与错误信息。
- 原因：保持一致的 UI 行为；用户无需手填 URL，更便捷。

4) 上传逻辑
- 选择文件后：
  - 设置 `uploading` 状态，禁用重复操作；
  - 调用 `onUploadImage?.(file)` 或默认 `ImagesService.imagesControllerUpload({ file })`；
  - 成功取得 `url` 后，调用现有 `insertAtCursor("\n![图片](URL)\n")` 将图片以 Markdown 形式插入；关闭模态并清理选择框值；
  - 失败时展示错误信息并允许重试。
- 原因：与现有 Markdown 渲染保持一致，避免引入新的内容格式。

5) 体验增强（可选）
- 支持拖拽图片到编辑器区触发上传（监听 `onDrop` 并校验 `File` 类型）；
- 支持粘贴剪贴板图片上传（监听 `onPaste` 并从 `clipboardData.files` 读取）；
- 原因：提升常用输入路径的效率，非必需可后续迭代。

6) 安全与约束
- 前端校验文件类型与大小（如 <5MB），超限给出提示；
- 错误处理与登录态：上传失败或 401 时遵循项目拦截器行为，组件内显示友好错误文案；
- 原因：减少无效请求与提升可用性。

7) 验证
- 在论坛发帖与回帖编辑器中，点击“上传图片”能成功将本地图片上传并插入到正文；
- 预览模式下正确显示图片；失败场景提示清晰。

如您确认，我将按上述步骤实现并确保与现有 UI/接口保持一致，且不影响当前“通过 URL 插入图片”的功能。
