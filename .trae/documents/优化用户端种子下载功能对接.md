## 目标

* 按文档对接一次性下载：POST `/torrents/download-url` → GET `/download/{token}`，完成 `.torrent` 二进制下载与保存。

* 前端在权限、限流、错误语义、文件名与 MIME 处理上与文档保持一致；为后续扩展（如下载记录）预留接口。

## 现状确认

* 本仓库为前端（React + Vite）；服务端控制器/服务文件不在此仓库。已存在基于 OpenAPI 的前端客户端：

  * `TorrentsService.torrentsControllerCreateDownloadUrl`（POST `/torrents/download-url`）。

  * `DownloadsService.downloadsControllerDownload`（GET `/download/{token}`，返回 `Blob`）。

  * `TorrentsService.torrentsControllerRecordDownload`（可选记录下载行为）。

* 鉴权：`OpenAPI.TOKEN` 来自 `localStorage.accessToken`；路由守卫已有基本登录校验。

* 未见前端限流与统一的下载触发逻辑；未见对 Content-Disposition 文件名解析。

## 前端对接实现（新增与改造）

1. 新增下载逻辑封装（Hook + 工具）：

   * `src/features/download/useTorrentDownload.ts`：封装“生成链接→下载→保存”的流程，暴露 `downloadByTorrentId(torrentId, name)`。

   * `src/utils/http/saveBlobAsFile.ts`：处理响应头 `Content-Disposition` 文件名解析，fallback 为 `<name>.torrent`。

   * 原因：集中复用与测试，避免在页面散落重复实现；文件名与 MIME 解析抽象成工具，降低耦合。
2. 在种子列表/详情页面集成按钮：

   * `TorrentsPage` 列表项中增加“下载种子”按钮；调用 Hook 完成下载。

   * 若存在详情页，同步集成；无详情页则仅列表页集成。

   * 原因：将业务动作置于最接近用户的入口；统一交互与错误提示。
3. 下载记录（可选）：

   * 下载成功后调用 `torrentsControllerRecordDownload({ torrentId })`；失败不阻塞用户下载。

   * 原因：便于统计与风控；不影响用户体验。

## 权限与限流

* 权限门控：

  * 通过 `AccessContext.permissions` 判断是否包含 `download_torrent`；无权限则隐藏按钮或置灰并给出提示。

  * 原因：客户端尽量避免无效调用，提升体验并减少后端压力。

* 前端轻量限流：

  * 在 Hook 内对 `downloadByTorrentId` 做 5s 节流（按 `torrentId` 维度），超频直接提示“操作过于频繁”。

  * 原因：与文档限流策略对齐，降低触发 429 的概率；真正限流由服务端 `AbuseGuard/IpRateLimit` 保证。

## 下载流程与文件名

* 流程：

  * 调用 `torrentsControllerCreateDownloadUrl({ torrentId })` → 获取 `{ url }`。

  * 若返回的是绝对 URL，直接 `fetch(url)`；如仅返回 token，改用 `downloadsControllerDownload(token)`。

  * 解析响应：确保 `Content-Type=application/x-bittorrent`；从 `Content-Disposition` 提取文件名；fallback 使用传入的 `name` 或 `download.torrent`。

  * 使用 `URL.createObjectURL(blob)` + 动态 `<a download>` 触发保存，完毕后 `URL.revokeObjectURL`。

* 原因：严格遵循文档的响应语义与 MIME；客户端负责正确落盘与命名。

## 错误处理与提示

* 统一处理 HTTP 状态：

  * `401/403`：提示未登录或无权限；引导登录/申请权限。

  * `404`：提示“链接过期或已消费”，建议重新生成。

  * `429`：提示“触发限流”，建议稍后重试。

* 交互：

  * 使用现有通知组件（如全局 Message/Toast）；若无现成组件，临时退化为页面内错误文案或 `alert`。

* 原因：与文档错误语义一致，便于用户自助定位问题。

## 配置与环境变量

* 保持前端仅使用 `VITE_API_BASE_URL` 配置 `OpenAPI.BASE`；不接入服务端专用的 `TRACKER_*` 与 `FILE_BASE_URL`。

* 原因：Tracker 与 Passkey 加密为服务端职责，前端无需参与；避免引入无效或敏感配置。

## Swagger 对齐

* 校验当前生成的客户端是否覆盖文档端点；若 `openapi.json` 与生成客户端不一致，优先以生成客户端为准。

* 原因：以真实可用的客户端契约为准，避免前端与后端文档偏差导致对接失败。

## 验收与测试

* 功能验收：

  * 登录用户、具备 `download_torrent` 权限时，能正常生成链接并下载；无权限时不可见或不可用。

  * 连续点击在 5s 内仅触发一次；服务端返回 429 时正确提示。

  * 下载文件 MIME 与扩展名正确，文件名能从响应头解析或合理回退。

* 测试：

  * 为 `saveBlobAsFile` 编写单元测试，覆盖 `Content-Disposition` 解析（含 RFC 5987 编码）与回退逻辑。

  * 为 Hook 做最小集成测试（可用 Mock 的 `TorrentsService/DownloadsService`）。

* 原因：关键工具可测试，降低回归风险；端到端通过手测与联调验证。

## 迁移影响与不兼容说明

* 新增权限门控与限流提示会改变既有交互（例如按钮从始终可用变为按权限显示）。

* 新增 Hook/工具为独立模块，无需兼容旧逻辑（当前项目不存在旧的下载实现）。

* 原因：遵循“无旧代码兼容”规则，直接采用新实现，以清晰可靠为先。
