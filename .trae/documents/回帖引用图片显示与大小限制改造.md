## 背景与问题
- 现状：回帖引用区域仅截取父楼 `content` 的纯文本片段，未进行 Markdown 转 HTML 的渲染，导致图片语法显示为代码而非图片。
- 位置：`src/pages/forum/ForumPage.tsx:775-797`（引用块），其中 `postsMap.get(reply.parentId)?.content.slice(0, 200)` 以文本方式展示。

## 目标
- 在“回帖引用”中渲染图片（支持 Markdown `![]()` 与 `<img>`），并限制图片显示大小，防止撑破布局。
- 保持主体内容渲染逻辑不变，仅对“引用区域”增加图片大小限制。

## 方案设计
1. 新增专用渲染函数 `renderPreviewQuote(text: string): string`
   - 基于现有 `renderPreview` 的规则，额外对图片进行更严格的尺寸限制：
     - Markdown 图片：替换为 `<img class="max-w-full max-h-[160px] object-contain rounded-lg my-2" ...>`。
     - 原生 `<img>` 标签：为其注入同样的尺寸限制类或内联样式。
   - 对不安全 `src`（如 `javascript:`）做简易过滤，仅允许 `http(s)`。
2. 引用区域改用 HTML 渲染组件（复用 `ReplyContent` 或新增 `QuoteContent`）：
   - 将 `slice(0, 200)` 文本展示替换为 `dangerouslySetInnerHTML={{ __html: renderPreviewQuote(...) }}`。
   - 容器加类名（如 `quote-content`）确保样式一致。
3. 保持主体帖与回帖正文继续使用原有 `renderPreview`，不改变其图片大小（避免影响正文阅读）。

## 具体改动点
- `src/pages/forum/ForumPage.tsx`
  - 增加 `renderPreviewQuote` 实现（紧邻 `renderPreview`）。
  - 在引用块中将文本片段渲染替换为 HTML 渲染：`src/pages/forum/ForumPage.tsx:793-796`。
  - 如复用 `ReplyContent`，则为引用容器添加限制样式；如新建 `QuoteContent`，在组件中固定注入尺寸限制类。

## 安全与兼容
- 简单过滤图片 `src` 协议（仅 `http:`、`https:`），防止 XSS 风险。
- 不做旧代码兼容；引用区域将统一走 HTML 渲染路径。

## 验证
- 在回帖中引用含 `![](url)` 的图片：引用块应显示图片，且高度不超过 160px、宽度不超过容器宽度。
- 引用 `<img src="...">` 的内容同样受限。
- 正文图片大小保持原样，引用与正文显示效果区分明确。
