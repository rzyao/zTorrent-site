# 基于新增端点完善审核页前端对接方案

## 后端新增端点概览（已提供示例）
- 影片管理员通用列表：`POST /films/admin/list`（支持 `approvalStatus` 与 `approvedAt` 排序）
- 片单管理员通用列表：`POST /playlists/admin/list-playlists`（支持 `approvalStatus` 与 `approvedAt` 排序）
- 种子管理员高级列表：`POST /torrents/admin/list-torrents`（示例包含 `approvalStatus=pending` 的高级规则）
- 审核开关只读：`GET /settings/review-switches`
- 审核历史统一查询：`GET /audit/history?type=<film|playlist|torrent>&resourceId=<id>`

## 前端对接目标
- 审核页 `/review` 完整支持三类资源的“列表筛选 + 审核动作 + 审核历史”。
- 使用新增通用管理员列表端点替换现有兜底逻辑；移除模拟数据与占位。
- 审核开关只读展示改用新只读端点。

## 具体改动（文件与原因）
- `src/api` 层
  - 更新 OpenAPI 定义并重新生成 Service：新增/映射以下方法（原因：保证类型安全与统一封装）
    - `FilmsService.filmsControllerAdminList(params)` → `POST /films/admin/list`
    - `PlaylistsService.playlistsControllerAdminList(params)` → `POST /playlists/admin/list-playlists`
    - `SettingsService.settingsControllerGetReviewSwitches()` → `GET /settings/review-switches`
    - `AuditService.auditControllerHistory({ type, resourceId })` → `GET /audit/history`（可新增独立 Service 或置于 `CommonService`）

- `src/pages/ReviewPage.tsx`
  - 替换影片数据源：
    - 将 `fetchFilms` 改为调用 `FilmsService.filmsControllerAdminList`；
    - 映射 `approvalStatus` → 现有本地枚举 `ReviewStatus`；支持 `sortBy: 'approvedAt'` 与 `order`。
    - 原因：统一管理员列表能力，消除仅 `pending` 的限制，避免兜底到用户端列表导致状态不完整。
  - 接入片单数据源：
    - 实现 `fetchPlaylists` 调用 `PlaylistsService.playlistsControllerAdminList`；
    - 映射 `approvalStatus` 与基本字段（`title/visibility/owner` 等）。
    - 原因：完成三类资源的一致审核体验。
  - 审核开关读取：
    - 将只读展示效果由 `SettingsService.settingsControllerListSettingsByGroup('review')` 改为 `SettingsService.settingsControllerGetReviewSwitches()`；
    - 原因：新端点更精确且权限可控，避免拉取无关设置。
  - 审核历史：
    - 在“审核历史”模态打开时调用 `AuditService.auditControllerHistory({ type, resourceId })` 渲染时间线；
    - 原因：替换本地 `mockAuditHistory`，与后端日志保持一致。
  - 统一响应与错误处理：
    - 保留 `unwrapResponse()/extractErrorMessage()`；
    - 原因：兼容统一包裹与直返体，减少重复错误处理。
  - 清理：移除 `mockReviewItems/mockAuditHistory` 与相关占位逻辑。

- `src/routes/AppRoutes.tsx`
  - 保持 `/review` 使用 `PermissionRoute requiredPermissions={["review:write"]}` 不变。
  - 原因：审核页为管理端页面，需要权限控制。

## 映射与字段约定（前端适配）
- `approvalStatus`：`pending|approved|rejected` → 映射到本地 `ReviewStatus`。
- `approvedAt` 排序：统一在三类列表接口中支持；默认 `DESC`。
- 通用字段映射建议：
  - 影片：`id/title/posterUrl/category/year/rating/visibility/uploader(username/reputation)/createdAt` → 审核页展示字段
  - 片单：`id/title/coverUrl/type/visibility/ownerUserId/owner(username)/createdAt` → 审核页展示字段
  - 种子：`id/title/name/category/description/visibility/uploader(username/reputation)/uploadedAt/createdAt/screenshots` → 审核页展示字段

## 验证方案
- 状态筛选：`pending/approved/rejected/all` 切换后三类资源列表均正确更新；
- 关键词搜索：`keyword` 生效；
- 审核动作：`approve/reject` 成功后本地状态更新，刷新历史查询即可看到时间线；
- 审核开关：顶部只读展示与后端读数一致；
- 权限守卫：无权限用户无法访问 `/review`。
