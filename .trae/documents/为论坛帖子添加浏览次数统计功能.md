## 背景与现状
- 现有数据模型已包含主题的浏览数字段：`IForumThread.viewsCount`（`src/pages/forum/ForumPage.tsx`），UI会展示该值。
- 前端当前未显式调用“递增浏览数”的接口；后端可能在获取详情（`POST /forum/threads/get-thread`）时内部递增，未提供独立统计端点。
- 仓库不包含后端实现与数据库客户端，前端通过 SDK 调用外部后端接口。

## 目标
- 用户打开主题详情页时，稳定地为该主题增加浏览次数，并在列表与详情实时展示更新后的 `viewsCount`。
- 短时间内避免重复计数（防刷与刷新不重复）。
- 若需扩展到“单条回帖”的浏览计数，提供相应模型、接口与 UI 改动方案。

## 前端改动（不破坏现有交互）
1. 在 `src/pages/forum/ForumPage.tsx` 的“加载主题详情”流程中，详情加载成功后立刻触发一次浏览计数递增：
   - 若后端已在 `get-thread` 内递增：直接使用返回的最新 `viewsCount`，无需额外调用。
   - 若未递增：新增前端 SDK 方法 `forumThreadsControllerIncViews({ id })` 并在详情加载后调用。
2. 防重复计数：使用 `localStorage('forum:viewed:<threadId>')` 标记，设置 15 分钟 TTL；存在标记则不再递增。通过 `window.addEventListener('storage', ...)` 同步跨标签页状态。
3. 乐观更新 UI：递增成功后同步更新 `selectedThread.viewsCount` 以及列表中对应主题项的 `viewsCount`；请求失败时回滚到旧值。
4. 退出页面的后备方案（可选）：使用 `navigator.sendBeacon` 在 `visibilitychange` 或 `beforeunload` 时发送统计，提升成功率。

## SDK/接口层改动
- 若后端已支持在详情接口递增：无需改动 SDK，只需确保详情数据渲染取用最新 `viewsCount`。
- 若后端未支持：在 `src/api/services/ForumThreadsService.ts` 中新增方法 `forumThreadsControllerIncViews(dto: { id: string })`，指向 `POST /forum/threads/inc-views`，后端返回新的 `viewsCount`；前端在详情加载完成后调用该方法。

## UI展示
- 列表与详情头部已展示 `viewsCount`（图标+数字）；保留样式与结构，仅确保数值在成功递增后即时刷新。

## 测试与验证
- 单元测试：
  - 模拟详情加载→触发递增→断言 `viewsCount` 增加；
  - 设置本地防重复标记后再次进入详情→断言未触发递增；
  - 标记过期后再次进入→断言再次递增。
- 手动验证：连续刷新页面在 15 分钟内不应重复计数；清除标记或等待过期后再次进入应计数。
- 无后端时：为 SDK 统计方法打桩（返回 `viewsCount + 1`）以验证前端逻辑与 UI 更新。

## 扩展：回帖级浏览计数（可选）
- 模型：在 `IForumPost` 增加 `viewsCount: number` 字段。
- 接口：提供 `POST /forum/posts/inc-views`，并在回帖列表/详情返回该字段。
- UI：在每条回帖右侧显示浏览数；用户点击“查看原回复”或展开某楼层详情时触发递增。

## 变更影响与兼容
- 默认不做旧代码兼容；若新增 SDK 方法需要后端同步提供端点，否则前端将仅依赖详情接口的内置递增。
- 改动遵循现有文件结构与调用模式，不变更用户交互。

## 交付项
- 详情加载后的浏览计数递增逻辑（含防重复与乐观更新）。
- 可选的 SDK 扩展方法与接口约定。
- 单元测试（或打桩验证）与手动验证指南。
