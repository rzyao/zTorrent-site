## 目标
- 在路由中注册 `MessagesPage`，路径为 `/messages`，遵循现有受保护路由（登录态校验 + 统一布局）。
- 修改头部右上角“通知(Bell)”和“信箱(Mail)”按钮，点击后统一跳转到 `/messages`。

## 路由改动
- 文件：`src/routes/AppRoutes.tsx`
- 位置：受保护路由区域，与 `/torrents`、`/forum` 等同级（参考 `src/routes/AppRoutes.tsx:58-139`）。
- 改动点与原因：
  - 引入页面组件（具名导出）：`import { MessagesPage } from '../pages/MessagesPage';`
    - 原因：当前 `MessagesPage.tsx`为具名导出（`export function MessagesPage()`），与项目其它具名导入风格一致（例如 `ForumPage`）。
  - 新增受保护路由 `/messages`，包裹在 `AuthRoute` 与 `AppLayout` 内：保证需要登录才能访问，并复用统一头部/布局。

```tsx
// 顶部 imports 区新增（保持现有顺序即可）
import { MessagesPage } from '../pages/MessagesPage'; // 具名导入，避免默认导出错误

// 在受保护路由分组中添加：
<Route
  path="/messages"
  element={
    <AuthRoute>
      <AppLayout>
        {/* 详细注释：复用统一布局与鉴权，保证体验一致 */}
        <MessagesPage />
      </AppLayout>
    </AuthRoute>
  }
/>
```

## 头部跳转改动
- 文件：`src/components/Header.tsx`
- 位置：按钮定义行（参考 `src/components/Header.tsx:39-54`）。
- 改动点与原因：
  - 使用 `useNavigate`，为 Bell/Mail 两个 `Button` 添加 `onClick={() => navigate('/messages')}`。
    - 原因：保持按钮的现有样式与结构（含红点角标），无需改成 `NavLink`；与项目中 `LoginPageWrapper`/`RegisterPageWrapper` 的导航方式一致。

```tsx
import { NavLink, useNavigate } from 'react-router-dom'; // 新增 useNavigate

export function Header() {
  const navigate = useNavigate(); // 详细注释：声明路由跳转函数
  return (
    <header /* ...保持不变... */>
      {/* ...省略无关代码... */}
      <Button
        variant="ghost"
        size="icon"
        className="text-white hover:bg白/10 rounded-none relative"
        onClick={() => navigate('/messages')} // 点击通知跳消息中心
      >
        <Bell className="w-5 h-5" />
        <span className="absolute top-1 right-1 w-2 h-2 bg-red-500 rounded-full" />
      </Button>
      <Button
        variant="ghost"
        size="icon"
        className="text白 hover:bg白/10 rounded-none relative"
        onClick={() => navigate('/messages')} // 点击信箱同样跳消息中心
      >
        <Mail className="w-5 h-5" />
        <span className="absolute top-1 right-1 w-2 h-2 bg-red-500 rounded-full" />
      </Button>
      {/* 其它按钮保持不变 */}
    </header>
  );
}
```

## 验证步骤
- 登录状态下访问 `/messages`：应正常渲染 `MessagesPage`，并显示统一头部与布局。
- 未登录时点击右上角按钮：由于路由受 `AuthRoute` 保护，应重定向到 `/login`，与现有鉴权逻辑一致（参考 `src/routes/AppRoutes.tsx:43-47`）。
- 顶部右上角 Bell/Mail 点击交互：均应跳转到 `/messages`，样式与红点角标保持不变。
- 直接打开深链 `http://localhost:xxxx/messages`：应根据登录态显示页面或跳登录。

## 兼容性与风险控制
- 遵循现有路由架构（`AuthRoute` + `AppLayout`），不会破坏其它页面导航结构。
- 使用具名导入避免默认导出不匹配导致的运行错误。
- 不更改按钮DOM层级，避免影响现有样式与角标定位。
