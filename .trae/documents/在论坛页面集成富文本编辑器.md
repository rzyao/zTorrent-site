## 目标
- 将 `src/pages/forum/ForumPage.tsx` 的发帖与回帖输入从 `<textarea>` 替换为可预览、支持 Markdown/图片/链接的富文本编辑器组件 `RichTextEditor`。
- 保持现有后端交互与错误处理逻辑不变，仅替换输入与相关状态管理。

## 改动概览
- 引入并使用 `RichTextEditor` 管理新帖与回复内容（受控组件）。
- 将原来通过 `document.getElementById(...)` 获取值的方式改为 React `useState` 管理内容。
- “回复”按钮的 @提及逻辑改为直接操作 `replyContent` 状态，不再直接操作 DOM。
- 保留主题锁定时禁用发送的行为；编辑器仍可显示但不可发送。
- 可选增强：展示正文时支持 Markdown 渲染（如需）。

## 详细步骤
### 1) 引入组件
- 在 `src/pages/forum/ForumPage.tsx` 顶部新增导入：`import { RichTextEditor } from './RichTextEditor'`（同目录相对路径，避免路径别名差异）。

### 2) 新帖表单使用 RichTextEditor
- 新增状态：`const [newThreadTitle, setNewThreadTitle] = useState('')`、`const [newThreadContent, setNewThreadContent] = useState('')`。
- 将当前“标题”输入改为受控：`value={newThreadTitle}`、`onChange={e => setNewThreadTitle(e.target.value)}`。
- 将“内容”输入替换为：
  - `<RichTextEditor value={newThreadContent} onChange={setNewThreadContent} placeholder="输入帖子内容，支持Markdown格式和图片..." minHeight="300px" />`
- 更新“发布”按钮点击逻辑（原 556–581 行）：
  - 使用 `newThreadTitle.trim()` 与 `newThreadContent.trim()` 进行校验与提交；不再从 `document.getElementById(...)` 读取。
  - 成功后：`setShowNewPost(false); setPage(1); setNewThreadCategoryId(''); setNewThreadTitle(''); setNewThreadContent('');` 并刷新列表逻辑保持不变。

### 3) 回复输入使用 RichTextEditor
- 新增状态：`const [replyContent, setReplyContent] = useState('')`。
- 将“回复输入框”处（原 760–766 行）替换为：
  - `<RichTextEditor value={replyContent} onChange={setReplyContent} placeholder="写下你的回复，支持Markdown格式和图片..." minHeight="150px" />`
- 更新列表中“回复”按钮点击逻辑（原 716–731 行）：
  - 设定 `setReplyParentId(reply.id)`；根据被回复楼层作者，生成 `const mention = \\`@${reply.authorUsername || reply.authorId} \\``；
  - 若 `replyContent` 未以该前缀开头，则 `setReplyContent(mention + replyContent)`；移除对 `textarea` 的直接操作。
- 更新“取消”逻辑（原 747–757 行）：
  - `setReplyParentId(null)`；
  - 移除 `replyContent` 开头的 `@用户名 ` 前缀：`setReplyContent(prev => prev.replace(/^@[^\s]+\s/, ''))`。
- 更新“发送回复”逻辑（原 768–792 行）：
  - 使用 `replyContent.trim()` 校验并提交；成功后清空 `replyContent` 与 `replyParentId`，并刷新回复列表；保留锁定状态禁用按钮与提示。

### 4) 内容展示（可选增强）
- 若需要将帖子正文与回复的 Markdown 也渲染为 HTML，可复用 `RichTextEditor` 中的 `renderPreview` 规则，将详情页的正文与回复展示区域从 `whitespace-pre-wrap` 改为 `dangerouslySetInnerHTML={{ __html: renderPreview(content) }}`。当前计划不强制执行此项，以降低改动面；如确认需要展示富文本，我们再追加此增强。

### 5) 兼容性与安全
- 编辑器使用简单正则渲染 Markdown，若启用详情页 HTML 渲染，应注意潜在 XSS 风险（需要可信后端或引入 HTML 清洗）。本次仅替换输入不影响现有展示安全性。
- 不改动后端服务调用与分页逻辑；仅替换输入与状态管理，回归风险低。

### 6) 验证
- 在“全部/某板块”下发布新帖：输入标题与富文本内容，提交后列表刷新且表单清空。
- 在主题详情页回复：点击某楼层“回复”自动插入 `@用户名` 前缀，支持富文本；提交成功后列表更新并清空输入。
- 在锁定主题下：发送按钮禁用且显示提示；编辑器可输入但无法发送。

如确认上述方案，我将按以上步骤在 `ForumPage.tsx` 中完成替换与调整，并保持代码风格与现有 UI 一致。
